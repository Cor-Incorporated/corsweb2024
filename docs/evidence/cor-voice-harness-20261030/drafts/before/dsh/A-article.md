「この人はテストを書く人ですか」。面談でそう聞かれても、経歴書の年数からは答えられません。git（変更を1回ずつ記録する仕組み）の履歴には、変更とテストが同じコミット（1回分の変更の記録）に含まれた回数など、後から数え直せる事実が残っています。

Grift CLIはその事実を手元で取り出すOSSです。MITライセンスで、Cor.株式会社が作っています。この記事では自分のリポジトリで動かす手順と、出てきた数字をどう読むかを書きます。読む相手は人材紹介会社・SESの営業の方と、エンジニア本人です。

## 動かす前に決めること

執筆時点の版は0.9.1（2026-10-28公開）です。Python 3.11以上とgitが必要です。分析は手元で完結し、LLMを使わず、テレメトリを持たず、結果を自動で送りません。

Griftが出さないものも、先に書きます。技量の総合点、シニア／ジュニアなどのランク、採用の合否、AIを使ったかどうかの検出や減点です。観測できなかった値は0で埋めず、not_observedやunresolvedとして残します。

最初に決めるのは、どのリポジトリを対象にするかです。自分のリポジトリなら、本人の同意は自分で出せます。人の記録を預かる場合は、本人の同意と、何に使うかを先に確認してください。数字を出すことと、その数字で人を判断することは別です。

## 手順

1. Grift CLIを入れます。

   ```bash
   pipx install grift-cli
   ```

2. 対象のリポジトリへ移動し、`grift report`を実行します。

   ```bash
   cd <対象のリポジトリ>
   grift report
   ```

3. `.grift/report.json`と`.grift/report.md`ができます。`report.md`は人が読む用、`report.json`は機械が読む用です。まず`report.md`を開き、どの数字が自分の直感と違うかを見ます。

4. 気になった数字があれば、レポートを渡して`grift verify`を実行します。

   `grift verify`は、レポートに記録された条件で再計算します。同じ計算をやり直して値が一致するかを確かめることを、Griftでは検算と呼びます。一致すればVERIFIED、違えばMISMATCH、再計算できなければCANNOT_VERIFYです。VERIFIEDは、数字が正しいと保証する印ではありません。同じ条件で同じ値が出た、という印です。

## 数字の読み方

2026年8月のQiita記事（v0.5.6の時点）で、公開OSSのpallets/clickを測った例があります。テストの併修率（test co-change）は`0.2664 ratio（73 of 274）`でした。

これは、本人に帰属した本番コードの変更274件のうち、73件で同じコミットのテストも変わっていた、という意味です。0.2664は73を274で割った率です。`73 of 274`は「274件のうち73件」と読みます。

### 分母から読む

読む順は分母、分子、率です。率だけを見ると、分母が何件だったのかが分かりません。分母が小さいほど、1件の増減で率は大きく動きます。母数と、数えられなかった理由をセットで見ます。

例はv0.5.6の時点のもので、執筆時点の0.9.1とは版が違います。同じリポジトリでも、版が変われば値が変わる可能性があります。

### 言えないことを確かめる

次に、その値が何を数えたものかを確かめます。テストの併修率は、同じコミットでテストのファイルが変わった割合です。テストの中身が良いか、通ったかは見ていません。

ですから、この数字から、テストが通ったとは言えません。テストの質が高いとも、本人が優秀だとも言えません。言えるのは、同じコミットでテストのファイルも変わった回数です。

### 未観測を0にしない

値が0のときも、not_observedと書かれているときも同じです。not_observedもunresolvedも、観測できなかった値です。「実績がなかった」という意味ではありません。0で埋めると、観測できた0と、観測できなかった値の区別が消えます。Griftは0で埋めず、この区別を残します。

値はリポジトリによって変わります。人と比べるための値ではありません。

## 検算できることの意味

### 営業の場面

紹介会社・SESの営業の方にとって、検算できることは説明の材料です。「テストも変えながら進める人です」と言うときに、73 of 274を添えられます。相手のエンジニアは、同じレポートと条件があれば、その値を自分で計算し直せます。推薦の理由を、印象ではなく、分母付きの事実で話すための材料です。

ただし、検算が通るのは、入力と条件が同じときです。リポジトリが更新されれば値は変わります。比べるなら、同じ期間、同じ版、同じ条件で取ったレポート同士にしてください。MISMATCHは、記録と計算が食い違ったという意味です。CANNOT_VERIFYは、条件がそろわず再計算できなかったという意味で、記録が誤っているという意味ではありません。

### エンジニア本人の場面

エンジニア本人にとっては、自分の数字を先に見ておく意味があります。面談で聞かれる前に、分母の大きさ、テストの変え方、測れていない範囲を説明できると、数字は自分の言葉になります。

値が小さく見える項目があっても、隠す必要はありません。測れていない範囲を一緒に説明できることの方が、面談では役に立ちます。

## 判断するのは人

Grift CLIですることは3つです。入れて、対象のリポジトリで`grift report`を実行し、`grift verify`で確かめます。数字は率ではなく、分母と分子と、測れなかった理由で読みます。

Griftが出すのは、数えた結果と、数えられなかった理由です。人を点数で並べる道具ではありません。gitに残った事実を、後から検算できる形にする道具です。その事実をどう使うかは、読む人が決めます。

紹介会社・SES企業にはテスト導入（PoC）を個別に案内しています。料金も個別の案内です。
