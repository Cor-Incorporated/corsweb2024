「この人は、テストを書きながら仕事を進めるのか」。紹介会社やSESの営業の方が、推薦の理由を言葉にするときに迷うところです。エンジニア本人も自分の仕事の進め方を面談で説明しようとすると、言葉に詰まることがあります。

推薦の理由を「この人はテストも書きます」の一言で終えると、聞き手には根拠が伝わりません。逆に、数字だけを出すと、今度は数字の意味が分からないまま一人歩きします。

Grift CLIは、git（変更を記録する仕組み）に残った履歴から、後で検算できる事実を取り出すOSSです。MITライセンスで、Cor.株式会社が作っています。この記事では手元のリポジトリで動かす手順と、出てきた数字の読み方を書きます。

分析は手元で完結します。LLMを使わず、テレメトリを持たず、結果を自動で送りません。

## 何を出して、何を出さないか

Grift CLIが出すのは、gitに残った記録を、決めた条件で数えた結果です。技量の総合点、シニアやジュニアといったランク、採用の合否は出しません。AIを使ったかどうかの検出や減点も行いません。

人を評価するための点数を作る道具ではありません。記録から言えることを、言える範囲で残す道具です。読む側にも、数字をそのまま良し悪しに変換しない姿勢が要ります。

観測できなかった値は0で埋めません。0を入れると「数えた結果が0件だった」と読めてしまいます。観測できなかった値はnot_observedやunresolvedとして残します。「記録がなかった」と「実績がなかった」は別のことだからです。

## 手元で動かす

必要なのは、Python 3.11以上とgitです。執筆時点の版は0.9.1（2026年10月28日公開）です。

```bash
pipx install grift-cli
```

対象のリポジトリに移動して、`grift report`を実行します。

```bash
cd path/to/your-repo
grift report
```

`.grift/report.json`と`.grift/report.md`ができます。report.mdはそのまま読めます。

## レポートを検算する

`grift verify`は、レポートに記録された条件で再計算します。結果は3つです。

- VERIFIED: 再計算した値が記録と一致した
- MISMATCH: 一致しなかった
- CANNOT_VERIFY: 再計算できなかった

VERIFIEDは、記録が正しいことや、仕事の質が高いことを保証するものではありません。同じ条件で数え直したら同じ値になった、という意味です。

検算は、時間がたったあとや、別の人が読むときに効きます。レポートを渡された側は記録された条件のまま数え直せます。CANNOT_VERIFYは、値が違うという意味ではありません。再計算に必要な条件がそろわなかった、という意味です。

## 数字の読み方

2026年8月のQiita記事（v0.5.6の時点）では、公開OSSのpallets/clickを例にしました。test co-change（同じコミットでテストも変わった割合）は`0.2664 ratio（73 of 274）`と出ました。

これは本人に帰属した本番コード（製品の本体にあたるコード）の変更274件のうち、73件では同じコミット（変更を記録する単位）でテストも変わっていた、という意味です。分母は274、分子は73です。0.2664だけを眺めるより、73 / 274と読んだほうが、何を数えたのかが分かります。

この数字が示すのは、同じコミットでテストも変わったのが73件だった、ということだけです。テストが通った、テストの質が高い、本人が優秀だ、とは言えません。テストの中身や、変更が正しかったかは、この数字に入っていません。

読むときは、次の3つを一緒に確かめます。分母は何か。どの版で出した値か。観測できなかった項目はどれか。この3つが欠けると、数字は比較できません。数え方の条件が変われば、分母も分子も変わります。

比べるときは、版と条件をそろえてください。この例はv0.5.6の時点の値で、執筆時点の0.9.1とは版が違います。分母が何を数えたのか、どの版で出した値なのかを添えないと、数字は簡単に別の意味になります。

0件や低い値も、記録の上でそう数えられたという意味です。仕事の評価とは分けて読んでください。

## 読む立場ごとに

紹介会社・SESの営業の方へ。レポートの数字は推薦の理由を具体にする材料になります。「テストも一緒に変えている」と言うなら、73 / 274のように分母を添えてください。推薦の場面では、数字を並べるより、数字の意味を1行で添えるほうが伝わります。「本人に帰属した本番コードの変更274件のうち、73件でテストも変わっていました」のように、分母から読める形にしてください。テストが通ったことや、質の高さは、この数字だけでは言えません。

エンジニアの方へ。自分のリポジトリで一度動かすと、自分の記録がどう数えられるかが分かります。数字が低い項目があっても、それは仕事ができていないという意味ではありません。not_observedは「観測できなかった」という意味で、0件とは違います。まずは自分の記録で、何が観測され、何が観測されないかを確かめてください。

## 限界と結び

Grift CLIが扱うのは、gitに残った記録です。記録に残らない仕事はレポートにも出ません。数字は面談で聞くことを具体にするための材料です。レポートは面談の代わりではありません。判断するのは人間です。

紹介会社・SES企業にはテスト導入（PoC）を個別に案内しています。料金も個別の案内です。
