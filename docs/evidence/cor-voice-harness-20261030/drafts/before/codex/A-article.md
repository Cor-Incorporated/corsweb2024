Grift CLIを使うと、自分のリポジトリのgit履歴から、後で検算できる事実を取り出せます。人材紹介会社・SESの営業の方も、エンジニア本人も、出てきた数字を「何を数えた値か」まで戻って読むのが出発点です。

Grift CLIはCor.株式会社が作っている、MITライセンスのOSSです。技量の総合点や、シニア／ジュニアなどのランク、採用の合否は出しません。AIを使ったかどうかの検出や、それによる減点もしません。

数字で本人について説明するときほど、数字が示している範囲を確かめたい。レポートを作り、検算するところから始めます。

## 自分のリポジトリでレポートを作る

執筆時点のバージョンは2026年10月28日公開の[0.9.1](https://pypi.org/project/grift-cli/0.9.1/)です。実行にはPython 3.11以上とgitが要ります。インストールには次のコマンドを使います。

```bash
pipx install grift-cli
```

次に、分析したい自分のリポジトリで、次のコマンドを実行します。対象にするのは、その場所のgit履歴です。

```bash
grift report
```

実行すると、`.grift/report.json`と`.grift/report.md`ができます。レポートを作ったら、数字だけを抜き出す前に、その数字が何を数えたものなのかを読んでください。

営業の方が本人に説明を求める場合も、エンジニアが自分の仕事を説明する場合も、同じレポートを見ながら、値とその意味を確かめます。数字だけが独り歩きしないように、説明するときも対象と定義を添えます。

## レポートに記録された条件で検算する

続いて、次のコマンドを実行します。

```bash
grift verify
```

これはレポートに記録された条件で再計算するコマンドです。返ってくる結果は次のように読みます。

| 結果 | 意味 |
| --- | --- |
| `VERIFIED` | 再計算した結果が一致した |
| `MISMATCH` | 再計算した結果が一致しなかった |
| `CANNOT_VERIFY` | 再計算できなかった |

`VERIFIED`で確かめられるのは、記録された条件での再計算結果が一致したことです。本人の技量を認定したり、採用してよいと判断したりした結果ではありません。

`MISMATCH`と`CANNOT_VERIFY`も区別します。計算して違いが出たことと、再計算できなかったことは、同じ状態ではありません。レポートを読むときは、値とともに、検算がどの状態だったかも確認してください。

## テストが一緒に変わった割合を読む

数字の例として、2026年8月のQiita記事で使った、公開OSSのpallets/clickの結果を挙げます。当時のGrift CLIは[v0.5.6](https://pypi.org/project/grift-cli/0.5.6/)です。

テストが本番コードと同じコミットで変わった割合を表すtest co-changeは、次のように出ました。

```text
0.2664 ratio（73 of 274）
```

分母の274件は分析対象者本人に帰属した本番コードの変更です。そのうち73件では同じコミットでテストも変わっていました。`0.2664`という割合だけで読むより、「274件のうち73件」と、何の件数かを添えて読むと意味を追えます。

ここで数えたのは、本番コードとテストが同じコミットで変わったことです。テストが通ったことや、テストの質が高いこと、本人が優秀であることまでは、この値から言えません。

営業の方がこの数字を説明するなら、「テストを一緒に変えていた変更が、274件のうち73件あった」という範囲で伝えます。「だから優秀です」と評価を足すと、測った内容から離れてしまいます。

エンジニア本人も、数字を示すときは、何を数えたのかを説明してください。テストの内容や意図について話す場合は、レポートの値と、本人が補足する説明を分けます。値そのものに、仕事の背景まで語らせないためです。

この例はv0.5.6の時点の記録です。今回の手順で自分のリポジトリを分析した結果として、同じ数字を期待するものではありません。

## 観測できなかった値をゼロにしない

Grift CLIは観測できなかった値を0で埋めず、`not_observed`や`unresolved`として残します。

ここを「0だった」と読み替えると、観測できなかったことが、数えた結果ゼロだったことに変わってしまいます。数字がない箇所も、その状態のまま読んでください。本人の仕事についての説明に使うときも、「観測できなかった」と伝えるところまでです。

割合、分子と分母、検算の状態、観測できなかった値。それぞれが何を示すかを確かめると、レポートから言えることを具体的な言葉にできます。反対に、分からない部分を点数や推測で補うと、元の記録から離れてしまいます。

## 手元で実行し、数字の意味を確かめる

分析は手元で完結します。LLMを使わず、テレメトリも持たず、結果を自動で送りません。レポートを作ることと、結果を誰かに伝えることを混同せず、説明に使う数字を自分で確かめてください。

紹介会社・SES企業へのテスト導入（PoC）と料金は、個別に案内しています。

まずは自分のリポジトリでレポートを作り、検算して、ひとつの値を分子と分母から読んでみてください。数字の大きさに評価を足す前に、そこに何が記録されているのかを確かめる。そのための手順です。
