# cor-jp.com のブログ記事を新しく書いて、公開の準備をするまで

管理画面で日本語の記事を書き、公開に向けた検査を進める手順です。変更を取り込む操作（merge）と公開は代表が行います。

## 1. 管理画面を開く

[Sveltia CMS の管理画面](https://cor-jp-cms-admin.web.app/)を開きます。

## 2. 記事の基本情報を入力する

タイトルや日付など、記事の基本情報を入力します。これらの設定項目を frontmatter と呼びます。

| 項目 | 入れる内容 |
| --- | --- |
| `title` | 記事のタイトル |
| `description` | 記事の説明。空欄にしません |
| `pubDate` | 記事の日付 |
| `category` | `ai`、`engineering`、`founder`、`lab` のどれか |
| `tags` | 記事のタグ |
| `author` | `"Terisuke"` |
| `lang` | `"ja"` |

必要に応じて、次の項目も付けられます。

| 任意の項目 | 入れる内容 |
| --- | --- |
| `summary` | 2〜3 文の要約。記事の上の「この記事の要点」に表示されます |
| `image` | 記事の画像 |

## 3. 本文を書く

1. 日本語で本文を書きます。本文には営業の誘い文句を入れません。
2. 出典は記事の最後に `## 参考資料` という見出しを置き、その下にリンクの箇条書きでまとめます。
3. ISMS に触れる場合は、次の範囲で書きます。「取得済み」とは書きません。

   > 2026年10月に ISO/IEC 27001 の第2段階審査を終え、2026年12月ごろの認証登録を見込んでいる

## 4. 保存して、変更を取り込むための依頼を作る

CMS で保存すると、`develop` 向けの PR（変更を取り込むための依頼）ができます。保存しただけでは本番には公開されません。

`develop` 向けに PR を出すと、CI（自動処理）が英語・中国語・韓国語・スペイン語の訳を作り、PR に追加します。訳のファイルは手で直しません。

## 5. 文言・推敲・記事データを検査する

以下は公開準備で使う検査コマンドです。`<記事名>` は対象の記事の名前に置き換えます。`<記事>` は対象の記事ファイル、`<最終稿>` は書き直した原稿のファイルを指します。

1. 文言を検査します。

   ```
   npm run blog:check -- src/content/blog/ja/<記事名>.md
   ```

2. 推敲の準備をします。

   ```
   npm run polish -- prepare --file <記事>
   ```

3. 書き直したあと、最終稿を検査します。

   ```
   npm run polish -- check --file <記事> --final <最終稿>
   ```

4. 記事の基本情報などを含めて、build が通ることを確かめます。frontmatter が間違っていると、この検査で失敗します。

   ```
   npm run build
   ```

エンジニアは管理画面を使う代わりに `src/content/blog/ja/<記事名>.md` を直接作ることもできます。

## 6. merge と公開は代表が行う

記事の変更を取り込む操作（merge）と公開は代表が行います。`develop` から `main` へのリリースで、本番に公開されます。
