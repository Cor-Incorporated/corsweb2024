# cor-jp.com のブログ記事を新しく書いて、公開の準備をするまで

この手順書は、Cor.株式会社のウェブサイト（cor-jp.com）に新しいブログ記事を作成し、公開の準備をするまでの流れを説明します。主に新しく入られたスタッフの方向けで、エンジニアリングの知識は不要です。

---

## 記事の作成手順

### 1. 記事を書く

新しくブログ記事を書く方法は主に以下の2つです。

*   **管理画面（Sveltia CMS）を使う**：
    新しく入られたスタッフの皆さんは、通常、管理画面（Sveltia CMS: `https://cor-jp-cms-admin.web.app/`）を使って記事を作成します。管理画面で記事を保存すると、自動的に `develop` ブランチ向けのプルリクエスト（PR）が作成されます。
*   **Markdown ファイルを直接作成する（エンジニア向け）**：
    エンジニアは、`src/content/blog/ja/<記事名>.md` のパスに直接 Markdown ファイルを作成することもできます。

### 2. frontmatter（記事の基本情報）を記述する

記事の冒頭には、記事の基本情報である "frontmatter" を記述します。これは記事のタイトルや公開日などの情報で、管理画面で入力すると自動的に生成されます。直接 Markdown ファイルを作成する場合は、以下の項目を記述してください。

*   `title`: 記事のタイトル（例: `"新しい技術の紹介"`）
*   `description`: 記事の簡単な説明。SEO やプレビューに使われます。**空にすることはできません。**
*   `pubDate`: 記事の公開日（例: `2024-01-01`）
*   `category`: 記事のカテゴリ。以下のいずれかを指定します。
    *   `"ai"`
    *   `"engineering"`
    *   `"founder"`
    *   `"lab"`
*   `tags`: 記事に関連するタグのリスト（例: `["AI", "開発"]`）
*   `author`: 著者名（例: `"Terisuke"`）
*   `lang`: 記事の言語（`"ja"`）

**任意で追加できる項目:**

*   `summary`: 2〜3文程度の記事の要点。記事の本文の上にある「この記事の要点」欄に表示されます。（例: `"この記事では新しい技術について解説します。..."`）
*   `image`: 記事のメイン画像に関する情報。

### 3. 記事の内容を作成する

本文を記述する際のルールです。

*   **参考資料の記載**:
    記事の最後に `## 参考資料` という見出しをつけ、その下にリンクを箇条書きで記載してください。
*   **営業の誘い文句の禁止**:
    記事の本文中に、営業の誘い文句やコンサルティングへの直接的な誘導などは含めません。記事下部のCTAボックスがその役割を担います。
*   **ISMSに関する記述**:
    ISO/IEC 27001（ISMS）について記述する場合は、「2026年10月に ISO/IEC 27001 の第2段階審査を終え、2026年12月ごろの認証登録を見込んでいる」という表現までにしてください。「取得済み」や「認証取得」といった表現は使用しません。

### 4. 記事のチェックと推敲をする

記事を作成したら、公開前にいくつかのチェックを行います。

*   **文言の検査**:
    エンジニアが `src/content/blog/ja/<記事名>.md` を直接作成した場合、文言の検査は `npm run blog:check -- src/content/blog/ja/<記事名>.md` コマンドで行います。
*   **推敲の検査**:
    記事の推敲（文章の改善）を行う場合は、まず `npm run polish -- prepare --file <記事のパス>` コマンドを実行します。その後、提案された内容で記事を書き直し、最終稿に対して `npm run polish -- check --file <記事のパス> --final <最終稿のパス>` コマンドで確認します。
*   **技術的なビルドチェック**:
    frontmatter の記述が正しいかなど、技術的なエラーがないかは `npm run build` コマンドで確認されます。もし frontmatter に誤りがあると、このコマンドは失敗します。
*   **翻訳について**:
    英語、中国語、韓国語、スペイン語への翻訳は、この後の手順でPRを `develop` ブランチに提出すると、自動的にCI（継続的インテグレーション）システムが実行し、PRに追加されます。**翻訳されたファイルを手動で修正する必要はありません。**

### 5. プルリクエスト（PR）を作成する

管理画面（Sveltia CMS）で記事を保存した場合、自動的に `develop` ブランチ向けのPRが作成されます。直接 Markdown ファイルを作成した場合は、`develop` ブランチを対象としたPRを作成してください。

このPRが作成されると、CIシステムが起動し、自動的に他言語への翻訳ファイルが生成され、PRに追加されます。

### 6. 記事の公開

最終的な記事の `develop` ブランチから `main` ブランチへのマージ（統合）と、本番環境への公開は代表が行います。
