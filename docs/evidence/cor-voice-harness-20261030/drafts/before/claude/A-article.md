候補者を推薦する理由を、経験年数のほかに何と言えばよいのか。紹介会社やSESの営業の方からこの問いを聞きます。エンジニア本人にも、経歴書の言葉のほかに自分の仕事を示す材料がありません。

Grift CLIはgit（ソフトウェアの変更を記録する仕組み）の履歴から、あとで検算できる事実を取り出すOSSです。MITライセンスで、Cor.株式会社が作っています。この記事では自分のリポジトリで動かす手順と、出てくる数字の読み方を書きます。

## 先に、出さないもの

Grift CLIは技量の総合点を出しません。シニアやジュニアといったランクも、採用の合否も出しません。AIを使ったかどうかの検出や、それによる減点もしません。

観測できなかった値は0で埋めません。`not_observed`（観測できなかった）や`unresolved`（決められなかった）として残します。0は「なかった」という主張で、`not_observed`は「見えなかった」という記録です。レポートの中ではこの2つを別のものとして扱います。

分析は手元で完結します。LLMを使わず、テレメトリ（利用状況を送る仕組み）を持たず、結果を自動で送りません。レポートを誰に見せるかは、実行した本人が決めることになります。

## 動かす手順

Python 3.11以上とgitが要ります。執筆時点の版は[v0.9.1](https://pypi.org/project/grift-cli/)で、2026年10月28日に公開しました。

入れ方はpipxです。

```bash
pipx install grift-cli
```

対象のリポジトリに移動して、レポートを作ります。

```bash
cd <対象のリポジトリ>
grift report
```

`.grift/report.json`と`.grift/report.md`ができます。読むときは`report.md`を開きます。レポートはこのフォルダにできるだけで、自動でどこかへ送られることはありません。

できたレポートは検算にかけられます。

```bash
grift verify
```

`grift verify`はレポートに記録された条件で再計算し、結果を3つのうちのどれかで返します。

- `VERIFIED`: 再計算した値がレポートと一致した
- `MISMATCH`: 再計算した値がレポートと違った
- `CANNOT_VERIFY`: 再計算できなかった

`CANNOT_VERIFY`は「違った」ではありません。再計算そのものができなかったという結果なので、`MISMATCH`と混ぜずに読みます。レポートを受け取った側も同じ手順で確かめられます。推薦の文に数字を書くなら、受け取った人が自分で検算できる形になります。

## 数字の読み方

2026年8月のQiitaの記事（v0.5.6の時点）では、公開OSSのpallets/clickを例にしました。そのとき、test co-change（本番コードを変えたコミットで、テストも同時に変えた割合）は`0.2664 ratio（73 of 274）`と出ました。

この数字は本人に帰属した本番コードの変更274件のうち、73件では同じコミットでテストも変わっていた、という意味です。

読むときは`0.2664`ではなく`73 / 274`と読みます。率だけでは、母数がいくつなのかが分かりません。分子と分母があれば、どのくらいの記録から出た値かが分かります。同じ`0.2664`でも、母数が違えば読み方は変わります。

この数字から言えないことも書きます。テストが通ったとは言えません。テストの質が高いとも言えません。本人が優秀だとも言えません。同じコミットでテストのファイルも変わっていた、という事実だけです。面談で「このときのテストは何を確かめるものでしたか」と聞くための材料であって、答えそのものではありません。

`not_observed`や`unresolved`が出たときは、「なかった」と読まずに「見えなかった」と読みます。gitの履歴に残っていない仕事はレポートに出ません。履歴に残っていないことと、仕事をしていないことは別です。

数字を人に見せるときは、版と実行した条件を一緒に添えます。上の例はv0.5.6の時点のもので、この記事で手順を書いたv0.9.1とは版が違います。`grift verify`が再計算に使うのもレポートに記録された条件です。版と条件が抜けた数字は、受け取った人が検算できません。

## 営業の方とエンジニアの方へ

紹介会社やSESの営業の方は、推薦の理由を「274件のうち73件で、テストも同じコミットで変わっていた」のように、分母付きで書けます。候補者の順位や採用の合否に使うのは、利用規範に反する使い方です。数字は順位をつけるためではなく、面談で聞くことを具体にするための材料です。

エンジニアの方は自分のリポジトリで動かして、経歴書の言葉に根拠を添えられます。レポートは手元にでき、自動では送られません。出すかどうか、誰に出すかは本人が決めます。

紹介会社・SES企業にはテスト導入（PoC）を個別に案内しています。料金も個別の案内です。数字から何を判断するかは、読む人が決めます。
