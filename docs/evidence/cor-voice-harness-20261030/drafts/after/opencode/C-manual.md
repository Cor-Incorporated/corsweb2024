# cor-jp.com のブログ記事を新しく書いて、公開の準備をするまで

この手順書は cor-jp.com のブログ記事を初めて書くスタッフ向けです。記事を書いて検査を通し、公開の準備ができるところまでを扱います。merge と公開は代表が行います。

## 記事を書く

記事は管理画面で書けます。

1. ブラウザで https://cor-jp-cms-admin.web.app/ を開きます。Sveltia CMS の管理画面です。
2. 記事を書いて保存します。保存すると、develop 向けの PR（変更を取り込んでもらう依頼）ができます。

エンジニアが書く場合は、`src/content/blog/ja/<記事名>.md` を直接作ってもかまいません。

## frontmatter を埋める

frontmatter は記事の冒頭に置く設定です。次の項目を書きます。

| 項目 | 書く内容 |
|---|---|
| title | 記事の題 |
| description | 記事の説明。空にしない |
| pubDate | 公開する日付 |
| category | ai、engineering、founder、lab のどれか |
| tags | 記事のタグ |
| author | "Terisuke" |
| lang | "ja" |
| summary（任意） | 2〜3 文。記事の上の「この記事の要点」に出る |
| image（任意） | 記事の画像 |

## 本文を書くときの決まり

1. 出典は本文の最後に置きます。「## 参考資料」の見出しを作り、リンクの箇条書きで書きます。
2. 本文に営業の誘い文句を入れません。
3. ISMS について書くときは、「2026年10月に ISO/IEC 27001 の第2段階審査を終え、2026年12月ごろの認証登録を見込んでいる」までにします。「取得済み」とは書きません。

## 検査を通す

1. 文言を検査します。`npm run blog:check -- src/content/blog/ja/<記事名>.md` を実行します。
2. 推敲の準備をします。`npm run polish -- prepare --file <記事>` を実行します。
3. 記事を書き直し、最終稿を保存します。
4. 最終稿を検査します。`npm run polish -- check --file <記事> --final <最終稿>` を実行します。
5. build を通します。`npm run build` を実行します。frontmatter が間違っていると、ここで落ちます。

## 訳ができるのを待つ

PR を develop に出すと、CI が英語・中国語・韓国語・スペイン語の訳を作り、その PR に足します。訳のファイルは手で直しません。

## merge と公開

merge と公開は代表が行います。develop から main へのリリースで、本番のサイトに出ます。

検査が通り、訳がそろったら、代表に merge を依頼します。
