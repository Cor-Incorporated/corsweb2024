# cor-jp.com のブログ記事を新しく書いて、公開の準備をするまで

この手順書は、Cor.株式会社のウェブサイト（cor-jp.com）に新しいブログ記事を書き、公開の準備をするまでの流れを説明します。主に新しく入ったスタッフの方が、エンジニアの助けなしに記事を作成できるように書かれています。

## 1. 記事を書く

記事は次のどちらかの方法で書けます。

1.  **管理画面（Sveltia CMS）を使う:**
    *   ウェブブラウザで [https://cor-jp-cms-admin.web.app/](https://cor-jp-cms-admin.web.app/) を開きます。
    *   管理画面の指示に従って記事を作成・編集し、保存します。保存すると、エンジニアがコードの変更を確認するための「Pull Request」（PR）が自動的に作成されます。
2.  **直接ファイルを作成する（エンジニア向け）:**
    *   エンジニアは `src/content/blog/ja/<記事名>.md` という名前で新しいMarkdownファイルを作成し、記事を直接書き始めることもできます。

## 2. 記事の基本情報（Frontmatter）を設定する

記事の一番上には、記事のタイトルや公開日などの基本情報を書きます。これを「Frontmatter」と呼びます。以下の項目は必ず入れてください。

*   `title`: 記事の題名です。
*   `description`: 記事の簡単な説明です。検索エンジンや記事の一覧に表示されます。**空にしないでください。**
*   `pubDate`: 記事の公開日です。（例: `2024-01-01`）
*   `category`: 記事の分野です。次の4つのどれかを選んでください: `ai`、`engineering`、`founder`、`lab`
*   `tags`: 記事の内容を表すキーワードを複数設定できます。（例: `["AI", "LLM", "生成AI"]`）
*   `author`: 記事の執筆者名です。必ず `"Terisuke"` と入力してください。
*   `lang`: 記事の言語です。日本語記事なので必ず `"ja"` と入力してください。

**任意で追加できる項目:**

*   `summary`: 記事の要点（2〜3文）です。記事の本文の前に「この記事の要点」として表示されます。
*   `image`: 記事のサムネイル画像を設定できます。（例: `url: "/images/blog/your-image.avif"`, `alt: "画像の説明"`）

**Frontmatterの例:**

```yaml
---
title: "新しいブログ記事の書き方"
description: "Cor.株式会社のブログ記事作成ガイド"
pubDate: 2024-07-26
category: "engineering"
tags: ["ガイド", "ブログ"]
author: "Terisuke"
lang: "ja"
summary: "この記事では、Cor.株式会社のブログ記事を新しく書く手順と、公開前の準備について説明します。初めての方でも安心して記事を作成できるよう、具体的なステップを追って解説します。"
---
```

## 3. 記事本文を書く際の注意点

*   **参考資料の記載:** 記事の最後に「## 参考資料」という見出しを作り、その下に参考にしたウェブサイトや書籍のリンクを箇条書きで追加してください。
*   **営業の誘い文句:** 記事の本文中には、営業目的の誘い文句（例: 「ぜひお問い合わせください」）を入れないでください。
*   **ISMSに関する記述:** ISO/IEC 27001（情報セキュリティマネジメントシステム）について書く場合は、「2026年10月に ISO/IEC 27001 の第2段階審査を終え、2026年12月ごろの認証登録を見込んでいる」という表現に留めてください。「取得済み」という言葉は絶対に使わないでください。

## 4. 記事の日本語の文言を検査する

記事を書き終えたら、以下のコマンドで文言の検査を行います。これはエンジニアが行う作業ですが、内容を理解しておくと良いでしょう。

*   **文言の検査:**
    *   `npm run blog:check -- src/content/blog/ja/<記事名>.md`
    *   このコマンドは、記事の表現が会社の定めるルールに沿っているかを自動で確認します。問題が見つかった場合は、表示されるメッセージに従って記事を修正してください。

*   **推敲の検査（日本語の記事のみ）:**
    *   まず、`npm run polish -- prepare --file <記事>` を実行します。
    *   この結果を参考に記事を修正した後、`npm run polish -- check --file <記事> --final <最終稿>` を実行して、最終稿が推敲の基準を満たしているかを確認します。

## 5. 記事の翻訳について

記事が日本語で書かれると、Pull Request（PR）を `develop` 環境に出した際に、自動的に英語、中国語、韓国語、スペイン語に翻訳されます。

*   **自動翻訳:** 翻訳は自動で行われるため、英語やその他の言語の翻訳ファイルを**手で修正しないでください**。もし修正が必要な場合は、元の日本語の記事を修正してください。そうすれば、次の翻訳時に正しい内容が反映されます。

## 6. 公開前の最終確認

公開前には、エンジニアが次の最終確認を行います。

*   **ビルドの成功:** `npm run build` コマンドを実行し、ウェブサイトが正しく構築されるかを確認します。Frontmatterに誤りがある場合、この段階でエラーが発生します。
*   **代表による最終承認と公開:** 記事の最終確認が完了し、`develop` 環境から `main` 環境へのリリースが行われると、記事が本番サイトに公開されます。この最終的なマージと公開は、代表が行います。
