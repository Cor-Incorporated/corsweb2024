Grift CLIはgitの履歴から、後で検算できる事実を取り出すOSSのコマンドです。MITライセンスで、Cor.株式会社が作っています。

人材紹介会社やSESの営業の方と、エンジニア本人に向けて書きます。手元のリポジトリで動かす手順と、出てきた数字の読み方を整理します。数字だけが先に伝わると、読み手は意味を取り違えます。数字には数えた条件が付きます。

執筆時点の版は[0.9.1](https://pypi.org/project/grift-cli/)です（2026年10月28日公開）。Python 3.11以上とgitが必要です。

## 入れ方とレポート

pipxで入れます。`pipx install grift-cli` は、Grift CLIを手元の環境に入れるコマンドです。

```
pipx install grift-cli
```

対象のリポジトリで、次のコマンドを実行します。

```
grift report
```

すると、`.grift/report.json` と `.grift/report.md` ができます。レポートには数えたときの条件が記録されます。レポートを渡された人が後から同じ条件で数え直せます。後で検算できるというのは、この部分です。

## 検算する

`grift verify` は、レポートに記録された条件で再計算します。レポートと検算の結果を一緒に渡すと、受け取った側も同じ手順をたどれます。結果は次のとおりです。

| 結果 | 意味 |
|---|---|
| VERIFIED | 再計算した値がレポートと一致した |
| MISMATCH | 再計算した値がレポートと違った |
| CANNOT_VERIFY | 記録された条件では再計算できなかった |

VERIFIEDは同じ条件で数え直すと同じ値になった、という意味です。記録が完全であることや、仕事の質が高いことは意味しません。

結果がVERIFIED以外なら、値だけで判断せず、記録された条件を確かめます。VERIFIEDでも、記録そのものが正しいかまでは分かりません。

結果はレポートを読むときの最初の関門です。CANNOT_VERIFYのときは、値を読む前に、何が足りないのかを確かめます。分からないまま率だけを取り出すと、意味が変わります。

## 数字は分母から読む

2026年8月のQiita記事では、v0.5.6の時点で、公開OSSのpallets/clickを測った例を紹介しました。

test co-change（テスト併修率、同じコミットでテストも変えた割合）は `0.2664 ratio（73 of 274）` でした。本人に帰属した本番コードの変更274件のうち、73件で同じコミットのテストも変わっていたという意味です。

先に読むのは `0.2664` ではなく、`73` と `274` です。率は分子を分母で割った値です。`73 ÷ 274` が `0.2664` に当たります。率だけを見ると、分母の大きさが分かりません。

何を274件と数えたのか。73件は何に当たったのか。どちらかが決まらないと、率だけを見ても意味がありません。分母が違えば、同じ率でも意味が変わります。

ここから言えるのは、テストも変えた変更が73件あった、というところまでです。テストが通ったとは言えません。テストの質が高いとも言えません。本人が優秀だとも言えません。

数字は面談で聞くことを具体的にする材料になります。「テストを同じコミットで変えることが多いですね。どういう方針で進めていますか」と聞けます。合否や順位の材料にはしません。

## 読む順番

数字を見るときは、次の順で確かめます。

1. レポートに記録された条件を見る。どの範囲の変更をどの条件で数えたのかを確かめます。
2. 分母を見る。何件を数えたのかを見ます。
3. 分子を見る。そのうち何件が目的の出来事に当たったのかを見ます。
4. 観測できなかった値を見る。`not_observed` や `unresolved` が残っていないかを見ます。
5. 数字を面談で聞く質問に変える。

この順番を飛ばして率だけを見ると、意味を取り違えます。

## 出さないもの、0で埋めないもの

Griftが出さないものは決まっています。数字が足りないからではなく、出力として出さないと決めているものです。

- 技量の総合点
- シニア／ジュニアなどのランク
- 採用の合否
- AIを使ったかどうかの検出や減点

総合点がないため、複数人を1つの物差しで並べることはできません。

観測できなかった値は0で埋めません。`not_observed` や `unresolved` として残します。

0は「測って、0だった」です。`not_observed` は「測れなかった」です。同じ0として扱うと、読む意味が変わります。

値が0なのか、測れなかったのか。ここを分けて読むだけで、次の行動が変わります。`unresolved` も決められなかった値を残すための語です。

## 手元で完結する

分析は手元で完結します。LLMを使わず、テレメトリを持たず、結果を自動で送りません。リポジトリの中身を預ける前に、この点を確かめられます。

レポートを読むときは、数字を数えた条件を確かめながら読みます。条件が分からない値は、判断に使わない方がよいと考えています。

## 試すとき

紹介会社・SES企業にはテスト導入（PoC）を個別に案内しています。料金も個別の案内です。記録を見るときは、まずレポートの条件と`not_observed`を見ます。そのうえで、数字の背景を面談で聞きます。数字が良いか悪いかを決めるのは、面談と仕事の内容です。

まずは自分のリポジトリで動かし、`grift verify` まで通してみてください。出てきた数字が何を数えたものかを、自分の目で確かめられます。

エンジニアの方は、自分の記録を評価として受け取る必要はありません。何が記録され、何が記録されていないかを見る材料です。
