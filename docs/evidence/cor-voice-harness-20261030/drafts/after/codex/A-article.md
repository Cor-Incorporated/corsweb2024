Grift CLIを使うと、自分のgit履歴から後で検算できる事実を取り出せます。エンジニア本人には変更の記録を説明する材料になります。人材紹介会社やSESの営業の方には、本人と記録を確かめながら話すための材料になります。

Cor.株式会社が作る、MITライセンスのOSSです。執筆時点のバージョンは[0.9.1](https://pypi.org/project/grift-cli/)で、2026-10-28に公開しました。

## 自分のリポジトリでレポートを作る

Python 3.11以上とgitを用意します。Grift CLIのインストールには次のコマンドを使います。

```
pipx install grift-cli
```

次に、分析したい自分のリポジトリへ移動します。そのリポジトリで実行するのが、次のコマンドです。

```
grift report
```

実行すると、`.grift/report.json`と`.grift/report.md`ができます。まずは`.grift/report.md`を開き、出てきた数字を読んでみてください。

ここでは、数値だけを抜き出さず、何を数えた値なのかを一緒に読みます。同じ「割合」でも、何を分母にしたかで意味は変わります。本人のどの変更を数え、そのうち何件が条件に当たったのか。営業の方と共有するときも、この説明を数字と切り離さないようにします。

## テストを同時に変えた割合を読む

読み方の例として、過去の記事の数字を使います。2026年8月のQiita記事で扱った、公開OSSの`pallets/click`です。これはv0.5.6当時の記録です。今回、0.9.1で測り直した結果ではありません。

その例では、test co-changeが次のように出ました。これは、本番コードとテストを同じコミットで変更した割合です。

```
0.2664 ratio（73 of 274）
```

小数だけを見る前に、`73 of 274`を読みます。分母の274件は本人に帰属した本番コードの変更です。分子の73件は、そのうち同じコミットでテストも変わっていた変更です。レポートの数字を説明するなら、まずこの関係を言葉にします。

「本人に帰属した本番コードの変更274件のうち、73件では同じコミットでテストも変わっていました」。この言い方なら、何を観測したかを追えます。

一方、この数字から、テストが通ったとは言えません。テストの質が高いとも、本人が優秀だとも言えません。記録されているのは、同じコミットで変更されたという事実です。テストの成否や質まで読み込むと、数字が示す範囲を超えてしまいます。

営業の方が本人に聞くなら、「本番コードと一緒に、テストでは何を変えたのですか」と、記録の中身を聞く形にできます。本人もその変更について説明できます。割合を評価の言葉に置き換える前に、実際の変更について話す。そのための材料として読むと、数字の意味を保てます。

## 記録された条件で検算する

レポートを作ったあとは、次のコマンドを実行します。

```
grift verify
```

`grift verify`はレポートに記録された条件で再計算します。返ってくる状態は次のように読み分けます。

| 状態 | 意味 |
|---|---|
| `VERIFIED` | 再計算した結果が一致した |
| `MISMATCH` | 再計算した結果が違った |
| `CANNOT_VERIFY` | 再計算できなかった |

`VERIFIED`が示すのは、記録された条件で結果が一致したことです。これを、本人の技量や採用の合否が確認されたという意味には使いません。先ほどのテストの例と同じく、何を確かめたかを限定して読みます。

`MISMATCH`と`CANNOT_VERIFY`も分けて扱います。再計算して違いが出たのか、再計算そのものができなかったのか。この区別を残してください。どちらの状態からも、本人の能力が低いと結論づけることはできません。

## 観測できなかった値の扱い

レポートでは観測できなかった値を0で埋めません。`not_observed`や`unresolved`という状態で残します。値を観測できた場合と、観測できなかった場合を混ぜずに読むためです。

たとえば、観測できなかった項目を、営業資料で一律に0へ置き換えないようにします。元のレポートが残した状態まで消してしまうと、何を確かめられたのかが伝わらなくなります。共有するときは、数字とともに、こうした状態もそのまま残してください。

Grift CLIが出すのは、git履歴から取り出せる事実です。技量の総合点や、シニア／ジュニアなどのランク、採用の合否は出しません。AIを使ったかどうかの検出や、それによる減点も行いません。レポートを読む側もその範囲を保って扱います。

## 分析と結果の共有

分析は手元で完結し、結果を自動で送りません。LLMを使わず、テレメトリも持ちません。この分析の動作と、作成したレポートを誰かと共有することは、分けて考えてください。

紹介会社・SES企業向けのテスト導入（PoC）は、個別に案内しています。料金も個別の案内です。

まずは自分のリポジトリでレポートを作り、数字の分子と分母、観測できなかった項目、検算の状態を確かめてみてください。営業の方と話すときも、その記録を手元に置き、何が分かったかを本人の言葉で説明するところから始められます。
