# cor-jp.com のブログ記事を新しく書いて、公開の準備をするまで

管理画面で日本語の記事を書き、検査と翻訳を経て、公開の準備をする手順です。merge（変更の取り込み）と公開は代表が行います。

## 記事を書いて保存する

1. [管理画面（Sveltia CMS）](https://cor-jp-cms-admin.web.app/)を開き、新しい記事を書きます。

2. 記事の基本情報を入力します。この情報を frontmatter と呼びます。

   | 項目 | 入力する内容 |
   |---|---|
   | `title` | 記事のタイトル |
   | `description` | 記事の説明。空にしません |
   | `pubDate` | 記事の公開日 |
   | `category` | `ai`、`engineering`、`founder`、`lab` のどれか |
   | `tags` | 記事に付けるタグ |
   | `author` | `"Terisuke"` |
   | `lang` | `"ja"` |

   `summary` と `image` は任意です。`summary` を付ける場合は2〜3文で書きます。記事の上の「この記事の要点」に表示されます。`image` には画像を指定できます。

3. 記事の本文を書きます。本文に営業の誘い文句は入れません。出典は記事の最後に `## 参考資料` の見出しを置き、リンクの箇条書きで記します。

   ISMS について書く場合は、次の表現までにします。

   > 2026年10月に ISO/IEC 27001 の第2段階審査を終え、2026年12月ごろの認証登録を見込んでいる

   「取得済み」とは書きません。

4. CMS で記事を保存します。保存すると、`develop` 向けの PR ができます。PR は変更内容を確認して取り込むための依頼です。この時点では本番のサイトには公開されません。

## 検査と翻訳を確認する

以下のコマンドは記事ファイルを対象にした検査です。`<記事名>`、`<記事>`、`<最終稿>` は、対象の記事名やファイルの場所に置き換えます。

5. 次のコマンドで文言を検査します。

   ```
   npm run blog:check -- src/content/blog/ja/<記事名>.md
   ```

6. 次のコマンドで推敲の準備をします。

   ```
   npm run polish -- prepare --file <記事>
   ```

7. 記事を書き直したら、次のコマンドで最終稿を検査します。

   ```
   npm run polish -- check --file <記事> --final <最終稿>
   ```

8. PR に翻訳が追加されることを確認します。`develop` 向けの PR を出すと、CI（自動処理）が英語・中国語・韓国語・スペイン語の訳を作り、同じ PR に足します。訳のファイルは手で直しません。

9. 次のコマンドが通ることを確かめます。frontmatter に間違いがあると、この検査で失敗します。

   ```
   npm run build
   ```

## 公開の担当と流れ

ここまでが公開の準備です。merge と公開は代表が行います。`develop` から `main` へのリリースで、本番のサイトに記事が出ます。

## エンジニアが記事ファイルを作る場合

エンジニアは CMS を使う代わりに `src/content/blog/ja/<記事名>.md` を直接作ってもかまいません。
