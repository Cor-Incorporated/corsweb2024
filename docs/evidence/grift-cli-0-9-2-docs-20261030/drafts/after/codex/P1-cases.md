0.9.2では、ホストにPythonを入れずに、grift-cliのリポジトリから作ったDockerイメージで実行できるようにしました。読みたいリポジトリは履歴を全部取得し、`/repo`に渡します。`git worktree`で作った作業ツリーは使えません。`grift update`も加え、実行中の環境を明示的に更新し、更新後の版を表示するようにしました。`grift update --check`はPyPIの最新版の情報を読むだけで、更新はしません。自動更新や、ふだんの測定コマンドから版を確かめる通信もありません。`grift contribute`は本人の同意後に提出用ファイルを手元に保存し、提出に必要な情報と提出先を表示します。自動では送りません。既定の`--door local`で作ったファイルを公開して提出する場合は、`--door public-pr`で作り直し、新しく表示された提出情報を使います。本人が出す公開PRでも、身元を伏せた代理PRでも、ファイルの中身は公開されます。

[0.9.2](https://github.com/Cor-Incorporated/grift-cli/releases/tag/v0.9.2)では、リポジトリの文脈を示す出力に、観測した履歴で初めて活動した年と最後に活動した年、タグの頻度の分子と分母を表示するようにしました。今も活動している人にも最後の活動年が表示されるため、離脱や退職を示すものではありません。タグの頻度は「タグ数 ÷ 活動期間の日数 × 365.25」の年換算の値で、観測したリリース回数ではありません。点数・順位・合否を出さないことは変わりません。
