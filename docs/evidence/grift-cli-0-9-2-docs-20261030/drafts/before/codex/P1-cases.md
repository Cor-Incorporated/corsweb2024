0.9.2では、手元のPCにPythonを入れずにDockerでgit履歴を読めるようにしました。Grift CLIのリポジトリをcloneしてイメージを作り、読みたいリポジトリを`/repo`に割り当てて実行します。履歴をすべて取得したリポジトリを使い、`git worktree`で作った作業ツリーは使いません。あわせて、実行中のCLIの環境を更新し、更新後の版を表示する`grift update`を加えました。`grift update --check`はPyPIの最新版の情報を読むだけで更新せず、`grift --version`は通信せずに手元の版を表示します。自動更新や、ふだんの測定に伴う版の確認の通信はありません。

[0.9.2](https://github.com/Cor-Incorporated/grift-cli/releases/tag/v0.9.2)では、`grift contribute`で、本人の同意後に提出用のファイルを手元へ保存し、提出IDや保存した内容のハッシュ値（SHA-256）、提出先のURLを表示するようにしました。自動では送信しません。既定の`--door local`で作ったファイルは公開の受け口に提出できず、公開するときは`--door public-pr`で作り直し、新しく表示された提出ID・ハッシュ値・提出用の情報（meta）を使います。本人による公開PRでも、身元を伏せる代理PRでも、提出するファイル自体は公開されます。リポジトリの文脈には、観測した履歴で人が初めて活動した年と最後に活動した年を表示します。最後に活動した年には今も活動している人も含み、離脱や退職を示しません。タグの頻度は、タグ数と活動期間の日数を添えた年換算の値で、実際に観測したリリース回数ではありません。点数・順位・合否を出さないことは変わりません。
