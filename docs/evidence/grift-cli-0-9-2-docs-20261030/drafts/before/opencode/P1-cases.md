0.9.2では、Dockerでの実行、環境の更新、提出物の作成、リポジトリの文脈（context profile）の表示を足しました。ホストにPythonがなくてもgriftを実行できるよう、Dockerfileを足しました。grift-cliのリポジトリをcloneして`docker build -t grift-cli grift-cli`でイメージを作り、読みたいリポジトリを`/repo`にmountして`docker run --rm -v "$PWD:/repo:ro" grift-cli repo`のように実行します。履歴は全部取得した状態でmountします。shallow cloneをmountすると、渡されたcommitだけで数え、`revision_completeness`が`complete: false`になります。`git worktree`で作った作業ツリーはmountしません。コンテナ内から履歴を読めず、exit 2で止まるためです。`--out`で書き出すときは`--user "$(id -u):$(id -g)"`を付けます。イメージには`git`と`openssh-client`だけを入れており、`gh`と`cosign`は入れていません。`contribute --open`とcosignを呼ぶ操作はホスト側で実行します。CIにもdockerのjobを足し、イメージの`--version`と、読み取り専用のmount・networkなしでの`repo`の観測を確かめています。コマンドと出力は変わりません。`grift update`は、実行中のgrift-cliの環境を明示的に更新し、更新後の版を表示します。実行中の環境がpipxの管理ならpipxで、それ以外は実行中のPythonの`-m pip`で更新し、PATHにある別の環境のpipは使いません。`grift update --check`はPyPIの最新版の情報を読むだけで更新せず、`grift --version`は通信せず手元の版を表示します。自動の更新と、ふだんの測定コマンドからの版の確認の通信はありません。通信できないときや更新に失敗したときはメッセージを出します。`grift contribute`は、本人が同意したあとに`.grift/contribution.json`を保存し、提出ID、PRに入れるファイル名、保存したバイト列のSHA-256を含むmetaとmanifestの行、2つの提出経路のURLを表示します。自動では送りません。既定の`--door local`で作ったv2のpayloadは公開の受け口に出せないため、公開して出すときは`--door public-pr`で作り直し、新しく表示されたID・hash・metaを使います。本人の公開PRの経路も、身元を伏せる代理PRの経路も、payloadそのものは公開されます。リポジトリの文脈（context profile）では、初めて活動した年と最後に活動した年、タグの頻度の分子と分母を表示します。`actor_turnover`の`joined`は観測した履歴で初めて活動した年、`last_active`は最後に活動した年で、今も活動している人も`last_active`に入るため、離脱や退職を示しません。`release_cadence`は「タグ数 ÷ 活動の期間の日数 × 365.25」の年換算（tags/year）です。たとえば43タグ・70日なら224.37 tags/yearになりますが、224回のリリースを観測したという意味ではありません。

[0.9.2](https://github.com/Cor-Incorporated/grift-cli/releases/tag/v0.9.2)では、実行中の環境を更新する`grift update`、本人の同意のあとに提出物を作る`grift contribute`、ホストにPythonを入れずにDockerで実行する手順、リポジトリの文脈（context profile）の表示を足しました。候補者本人が手元で計測するとき、Dockerを使えばホストにPythonを入れずに実行できます。`grift contribute`は、同意のあとに提出ID、PRに入れるファイル名、保存したバイト列のSHA-256を含むmetaとmanifestの行、2つの提出経路のURLを表示し、自動では送りません。身元を伏せる代理PRの経路でも、payloadそのものは公開されます。リポジトリの文脈（context profile）では、初めて活動した年と最後に活動した年、タグの頻度の分子と分母を表示します。`last_active`は今も活動している人も入るため、離脱や退職を示しません。`release_cadence`のtags/yearは年換算の値で、リリースの回数を観測したものではありません。0.9.2でも、点数・順位・合否を出さないことは変わりません。
