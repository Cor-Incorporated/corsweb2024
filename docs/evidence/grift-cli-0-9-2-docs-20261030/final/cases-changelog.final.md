0.9.2では、ホストにPythonを入れずに、grift-cliのリポジトリから作ったDockerイメージで実行できるようにしました。読みたいリポジトリは履歴を全部取得し、`/repo`に渡します。`git worktree`で作った作業ツリーは使えません。

`grift update`は、実行中の環境だけを更新し、更新のあとに入った版を表示するように変えました。PATHにある別の環境は使いません。`grift update --check`はPyPIの最新版の情報を読むだけで、更新はしません。自動の更新と、ふだんの測定コマンドが版を確かめる通信はありません。

`grift contribute`は本人の同意後に提出用ファイルを手元に保存します。自動では送りません。既定の`--door local`で作ったファイルは公開受け口に出せないため、提出ID・PR内のファイル名・meta行は表示せず、`--door public-pr`で作り直す手順だけを表示します。公開して提出するときは、作り直した実行が表示する提出ID・PR内のファイル名・meta行と、2つの提出経路のURLを使います。本人が出す公開PRでも、身元を伏せた代理PRでも、ファイルの中身は公開されます。

[0.9.2](https://github.com/Cor-Incorporated/grift-cli/releases/tag/v0.9.2)では、`grift report`のMarkdownにあるリポジトリの文脈の欄に、観測した履歴で初めて活動した年と最後に活動した年、タグの頻度の分子と分母を表示するようにしました。JSONの値は変わりません。今も活動している人にも最後の活動年が表示されるため、離脱や退職を示すものではありません。タグの頻度は「タグ数 ÷ 活動期間の日数 × 365.25」の年換算の値で、観測したリリース回数ではありません。活動期間が20日未満のリポジトリでは年換算せず、タグの数と日数だけを表示します。

新しいコマンドはなく、点数・順位・合否を出さないことも変わりません。分析の値を変える修正もありませんが、定義の版を上げたため、0.9.1で保存したレポートと照らし合わせは、0.9.2の`grift verify`では検算できなくなります（要求だけから作った案件のレポートなどの例外は、[移行の注意](https://github.com/Cor-Incorporated/grift-cli/blob/v0.9.2/docs/migration-v092.md)にあります）。
