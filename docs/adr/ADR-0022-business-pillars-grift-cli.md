# ADR-0022 事業の柱を5本にし、Grift を CLI（OSS）＋紹介会社向けテスト導入として扱う

## ステータス: Proposed (2026-10-20)

## 背景
- 社内資料「Grift・自社事業の現状まとめ（HP・Grift LP更新用、2026-10-20）」で、HP の記述が実態とずれていることが分かった。
  - Grift は 2026-02 に Web見積アプリとして着手 → 2026-08 に計測部分を CLI に切り出し → 2026-09 に旧Webアプリを停止し、人材紹介会社・SES の営業支援へ方針転換した。HP にはまだ「AI見積支援ツール」「Team Beta 検証中」、トップに旧アプリの見積デモ（参考コスト・納期・類似実績）が残っていた。
  - 事業の柱は 3本（Grift・ローカルLLM・AI受託）ではなく 5本（Grift／ローカルLLM・セキュアAI／ハードウェアAI／AI受託開発・導入支援／教育・地域）になっている。
  - ISMS は 2026-10-07 に第2段階審査を不適合なしで終え、2026-12 ごろの登録見込み。HP は「整備中」のままだった。
  - 会社概要（所在地・設立・代表者）がまとまったページが無かった。
- 代表の判断（2026-10-20）: 売上は載せない／Grift の旧プランは取り下げて「個別案内」／griftai.org の /team-beta・/estimate-audit はトップへ 301／エンジニアカフェは名前とロゴを載せる／福岡を代表する企業100選を活用する。

## 決定
1. **事業の柱は 5本**。トップ（`services2026`）・会社概要・FAQ・meta・Cloudia の会社知識で同じ並び・同じ言い回しを使う。進行中・予定のものは「準備中」「予定」「構想中」と分かる表現にする。
   - 相手先の名前は**エンジニアカフェだけ**出す（代表の承諾）。専門学校・資格団体・開発パートナー・福岡市の名前は出さない。
2. **Grift の説明を「git履歴から確かめられる事実を取り出す自社プロダクト（CLI は MIT の OSS）」に統一**する。キャッチは「経歴は盛れる。証拠は盛れない。」。トップの見積デモは撤去し、CLI の使い方の例と3つの約束（点数にしない／毎回同じ結果／どこにも送らない）に差し替える。
   - intent キー `grift-team-beta` は契約（ADR-0014）としてそのまま使い、意味を「Grift（CLI・紹介会社向けテスト導入）の相談」に読み替える。キーの改名はしない。
   - 紹介会社さま向けの取り組みは「テスト導入（PoC）」と呼び、CTA は「Griftを自社でテストしてみる」にする。「試行」は硬く伝わりにくいので使わない（代表の指摘、2026-10-20。griftai の ADR-0005 と同じ言い回し）。
   - Grift の思想を書いた記事（Qiita・note）へは、Grift の事例ページと `/llms.txt` からリンクする。
   - 業種別ページの第二 CTA は Grift ではなく `local-llm-poc` にする（業種の課題と Grift の新しい対象が合わないため。ADR-0010/0011 の「第二=Grift」を置き換える）。
3. **ISMS の表現（ADR-0007 の改訂）**: 「2026年10月に ISO/IEC 27001（ISMS）の第2段階審査を終え、2026年12月ごろの認証登録を見込んでいる」までは書いてよい。**登録が完了するまで「取得済み」「認証取得」とは書かない**。審査機関名は引き続き書かない。JSON-LD に `hasCredential` を使わない方針も維持する。登録後は ADR を改訂して表現を更新する。
4. **会社概要ページ `/company`（全5言語）を追加**する。所在地・設立（2023年12月）・代表者・事業の柱・情報セキュリティ・選出を載せ、表示した事実（設立・所在地・選出）を Organization JSON-LD（`foundingDate` / `address` / `award`）にも載せる（ADR-0017: 表示している内容だけを構造化データにする）。電話・メールは載せない（問い合わせは Cloudia）。
5. **AIO 用に `/llms.txt` を追加**する。中身はページに表示している事実だけにし、基準日を書く。
6. **ニュース**は確定した事実だけを追加する（Grift CLI の公開、ISMS 第2段階審査の終了、福岡100選の紹介）。教育パートナー契約・NIKKEI THE PITCH は公開可否の確認が取れてから。
7. 情報セキュリティ基本方針（`security.basicPolicy`）の事業列挙（「AI評価基盤『Grift』」）は ISMS の文書なので、この変更では触らない。改訂は ISMS の手順（版数・日付の更新）で行う。

## 理由
- 実態と違う製品説明・価格・認証表現は、慎重な企業顧客と回答エンジンの両方に誤った事実を広める。
- 柱と Grift の言い回しを1つにそろえると、ページ間・言語間・構造化データ・Cloudia の回答が食い違わない。

## 影響
- ADR-0007 の「ISMS は『整備中』表現のみ」と「Grift は『参考見積もり』」の項を本 ADR で置き換える。
- ADR-0010/0011 の業種別ページ第二 CTA（Grift）を `local-llm-poc` に置き換える。
- 非日本語の UI 文言（`src/i18n/locales/{en,zh,ko,es}.json`）は手で翻訳してそろえる。コンテンツ（news / cases / blog）の翻訳は ADR-0019 の CI が行う。
- 福岡100選のエンブレムは掲載条件（クリックで特設ページへ・2027年7月末まで）を `Fukuoka100Emblem` で担保したまま、トップの「地域とともに」と会社概要にも置く。

## 代替案
- **旧プランの価格を残す**: 代表判断で却下（正式価格が決まってから載せる）。
- **柱を 3本のまま説明文だけ直す**: 実態（ハードウェアAI・教育・地域）が抜けるため却下。
