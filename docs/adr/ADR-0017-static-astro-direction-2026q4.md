# ADR-0017 HP の技術方針（2026Q4）: 静的 Astro を継続し、Next.js へは移行しない

## ステータス: Accepted (2026-09-27)

置換: ADR-0002（Firebase App Hosting＋SSR 移行）、ADR-0003（Supabase 採用）

## 背景

- 2026-09-27 の棚卸しで、ADR-0002（SSR 移行）と ADR-0003（Supabase）が未実装のまま Accepted になっていることが分かった。実体は `firebase.json`（public: `dist`）による静的配信で、DB は使っていない。
- 社内で「滞在時間を伸ばすために Next.js へ移行したい」という提案があった。ただし、フレームワークを変えると滞在時間が伸びるという一次資料は見つからなかった。
- 同じ監査で、Astro の強み（初期 HTML に本文があり、JS がほぼ要らない）を自ら損なっている設定が見つかった。
  - 全ページの `<html>` に `x-cloak` があり、外部 CDN から読む Alpine.js が動くまでページ全体が非表示になる。CDN に届かなければ白紙になる。
  - robots.txt が `/_astro/`（描画に必要な CSS/JS）を拒否している。
  - ブログの hreflang が実在しない言語版や自分自身を別言語として宣言している。
  - 本文に表示していない FAQPage の構造化データを全ページに出している。
- Astro は 4.16.18（4 系の最終版、2024-12）で、2026-09-24 時点の最新安定版は 7.3.5。
- CEO が共有した 2026-09 時点の検索・生成 AI 対策のベストプラクティスは、「独自で役立つ本文」「クロール可能な技術基盤」「信頼できるエンティティ」を土台とし、特定のフレームワークを求めていない。

## 決定

1. サイトは Astro の静的出力のまま運用する。Firebase Hosting の静的配信を続け、adapter・SSR・DB は導入しない。動的な部品は既存の Cloudflare Workers（contact-chat など）が担う。
2. Next.js へは移行しない。
3. Astro は 4 → 5 → 6 → 7 の順に、1 メジャーごとに 1 PR で上げる。本番リリースは 7 に到達した時点で 1 回とする。各段階は URL 一覧・構造化データ・hreflang・ページごとの JS 量のスナップショット差分で検証する。
4. SEO / AIO の技術基盤として、次を守る。
   - 初期 HTML に本文があり、外部 CDN の JS を待たずに表示される。
   - robots.txt で、ページの描画に必要な CSS/JS を拒否しない。
   - AI クローラーは、検索用・学習用ともに許可する（CEO 決定 2026-09-27）。
   - 構造化データは、本文に表示している内容だけを宣言する。
   - hreflang は、実在する言語版だけを宣言する。
   - 会社（Organization）と著者（Person）は 1 か所で定義し、`@id` で参照する。
5. 滞在時間そのものは目標にしない。計測の主指標は、次ページへの遷移率、CTA のクリック率、Cloudia での会話開始から有効な商談までの到達とする（社内の経営方針資料 2026-09-25 版の主指標に合わせる）。

## 理由

- 工数: Astro の段階アップグレードは 5.5〜9.5 人日の見込み。Next.js への作り直しは 25〜40 人日（推定）で、5 言語ルーティング・OG 画像・RSS・構造化データの再実装を伴う。
- JS 量: ホームの JS は Astro で約 22KB（gzip、実測）。Next.js の静的書き出しは公表例で First Load JS 84〜105kB。
- 滞在時間は検索順位の直接の要因ではなく、「検索意図を満たしたか」が評価される。効くのは本文の構造・内部リンク・CTA の設計・計測であり、フレームワークではない。
- 静的配信のままなら、Core Web Vitals（特に INP）で有利な構造を保てる。

## 影響

- ADR-0002 と ADR-0003 は Superseded とする。
- Astro 6 以降は Node 22.12 以上が必要なため、CI の Node を 22 に上げる。
- Server Islands・Actions・Live Collections など、adapter を必須とする機能は使わない。必要になった場合は別の ADR で判断する。

## 代替案

- Next.js へ移行する: 工数・JS 量・移行の回帰リスクが大きく、目的（滞在の質）に直結しないため不採用。
- Astro を SSR 化する（ADR-0002）: DB 型の CMS を採らない限り不要。ADR-0018（Git ベースの CMS）により不要になった。
