# ADR-0025 チャット以外の連絡の手段（営業を避けながら、本物の問い合わせを取りこぼさない）

## ステータス: Proposed (2026-10-26)

代表が下の「決めてほしいこと」を選んだら、Accepted にして、選ばなかった案を「代替案」に移す。

## 背景

- 代表の悩み（2026-10-26）: 営業の連絡を避けたいので、電話番号やお問い合わせフォームは置きたくない。でも、連絡先がチャットボットだけだと、結局問い合わせが減って困る。
- `/contact` の連絡の手段は Cloudia（AI チャット）だけ。2026-09-13 に電話とフォームを取り下げ、Cloudia が落ちたときに手段が無くなるリスクを受容した（ADR-0005 の 2026-09-13 改訂、ADR-0013）。その撤回条件を発動するための監視は、まだ設定されていない（#322）。
- Cloudia が配信されないとき、利用者は「AIチャットを準備しています」のページで止まり、ほかの手段を案内されない（#352）。
- 一方、連絡先はすでに公開している。`company@cor-jp.com` はプライバシーポリシーと特定商取引法の表記に、電話番号は特定商取引法の表記に載っている。調べる気のある営業は、いまでもここにたどり着ける。
- チャットの開始数・途中でやめた数・送られた数は、サイトの側では数えていない（#252）。本番の D1 と受信箱には集計に使えるものがあるが、読むには代表の承認が要る。
- 調べた案と一次資料は `docs/contact-channels-research-2026-10.md` にまとめた。判断の要らないチャットの UX は #425 と Cor-Incorporated/cloudia#33 で直した。

## 選択肢

|---|---|---|---|---|
| A | チャットで確かめた人にだけ、日程調整のリンクを出す | 低 | 中 | ¥0〜¥1,600/人・月 |

| C | 有料の診断の申込みを入口にする | 低 | 低〜中 | 決済額の 3.6% |

## 決定（推し案）

3 段で足す。

### 1. いま足す: B「AI と話さずに伝言だけ残す」

- Cloudia の最初の画面（目的の選択肢の下）と、会話の途中のどこからでも、「AI と話さずに伝言だけ残す」を選べるようにする。
- 入力は今の引き継ぎと同じ項目（目的、お名前、メールアドレス、会社名（任意）、ご用件）。送り先も今と同じ `/api/contact/submit`。LLM を通らない（ADR-0005 の「PII はメールのみ・LLM 非経由」のまま）。`source` で伝言と会話を分ける。
- ボット対策に Turnstile を入れる。Cloudia の画面にウィジェットを置き、Worker の `TURNSTILE_SECRET` を本番で必須にする（#280）。
- 営業らしさの振り分けを先に入れる（Cor-Incorporated/cloudia#17 の 3 段階: すぐ通知 / 日次のまとめ / 隔離。自動では捨てない）。伝言は AI の会話を経ないので、最初はルール（定型の営業文句、送信元のドメイン、同じ内容の連投など）で判定する。伝言の本文を AI に読ませて判定するかは、#382 の後に決める。
- Cloudia が配信されていないときの `/contact/chat/` のページ（いまは「AIチャットを準備しています」だけ）に、同じ伝言の入口を出す。#352 の行き止まりを閉じる。#322 の合成監視が見ている文言（「AIチャットを準備しています」）は残す。
- `/contact` のページ自体にはフォームも電話番号もメールアドレスも出さない（ADR-0005 の改訂と ADR-0021 のガードはそのまま）。

### 2. 測ってから足す: A 日程調整

- まずは実装せず、担当者が返信のメールで予約のリンクを送る運用から始める（営業の目に触れない）。
- B の後の 2 か月の数字を見て、返信から打ち合わせまでの往復が負担になっていれば、Cloudia で genuine と判定され、連絡先の入力まで進んだ人にだけ、予約のリンクを出す。
- 道具は、cor-jp.com の Google Workspace が予約者のメール確認を使えるエディションなら Google カレンダーの予約スケジュール（新しい委託先が増えない）。使えなければ、1 回限りのリンクを出せるもの（TimeRex のワンタイム URL、Calendly の single-use link）を比べ直す。

### 3. あわせて検討する: F「広告メールお断り」の表記

- すでに公開している `company@cor-jp.com` の直前か直後に「広告宣伝メールの送信はお断りします」と書くと、同意のない広告宣伝メールは特定電子メール法で送れなくなる（施行規則第 3 条）。費用はかからない。
- ただし `/privacy` と特商法のページは法務の文書なので、弁護士の確認を通してから変える（#382 と同じ流れ）。

### いまは採らない

- C 有料の診断を入口にする: 営業はほぼ止まるが、迷っている本物の相談者も減る。サービスのページで有料の診断を売るかは、作業 C（ADR-0024）の判断に任せる。
- D LINE 公式アカウント: 誰でも友だち追加でき、相手の私用の LINE に会社の相談が入る。
- E 050 の AI 電話受付: 番号を出せば営業電話が来る。ADR-0011 の公開の条件（着信・転送・録音の案内・個人情報・弁護士の確認）も終わっていない。B と A で足りなければ、もう一度検討する。
- `/contact` にメールアドレスを出す: 人の営業は止まらない。F で歯止めをつけても、仕分けの手間は残る。
- G 取材専用の窓口: Cloudia の目的「取材・登壇・その他」と B で足りる。
- SNS の DM: 営業がよく使う経路で、目的と逆を向く。

## 理由

- B は新しい委託先を増やさず、集める個人情報も今の引き継ぎと同じ項目で、費用もかからない。AI と話したくない人と、Cloudia の調子が悪いときの両方を受けられる。営業も入ってくるが、振り分けで担当者の目に触れる量を抑えられる。
- 営業を減らす効き目が測られている手段は見つからなかった（「営業お断り」の表示も、ハニーポットも、二次資料の数字しかない）。だから、効き目の分からないものを一度に足すより、B を入れて数えてから A に進むほうが、何が効いたかを確かめられる。
- 電話番号とメールアドレスはすでに公開しているので、「`/contact` に出さない」ことで減らせている営業は、ついでに連絡してくる分にとどまる。新しい入口の営業の来やすさも、この前提で比べた（何も公開していない状態からの増分としては比べていない）。

## 測り方と見直し

- B を入れる PR で、#252 の計測イベントのうち問い合わせの分（Cloudia を開いた、目的を選んだ、連絡先の入力まで進んだ、送った、伝言を送った）を先に入れる。
- 毎月、次を数える: 会話経由と伝言経由の送信の数、分類（genuine / sales / spam）の内訳、担当者が「本物の問い合わせ」とした数。
- 見直しは ADR-0005 の定期見直しと同じ 2026-12-13 に行う。そのとき、次のどちらかなら案を変える（数字は代表が決める）。
  - 伝言経由の営業が多く、日次のまとめを見る手間が回らない → Turnstile の設定を強める、伝言の入口を目的の選択の後ろへ下げる
  - 本物の問い合わせが増えない → A を前倒しする、E を検討し直す

## 影響

- Cloudia（Cor-Incorporated/cloudia）: 伝言の入口、Turnstile のウィジェット、計測イベント。
- corsweb: `/contact/chat/` の代わりのページに伝言の入口（corsweb の `HandoffForm.astro` を流用できる）。`workers/contact-chat` の `source` の許可、ルールでの振り分け、`TURNSTILE_SECRET` の必須化。`src/config/contact-guards.ts` の B-3（自己ループの禁止）と C（未配信の判定）に、伝言の入口を足しても通ることをテストで固定する。
- ADR-0005: Cloudia の障害時に最小限の伝言の入口を戻すので、2026-09-13 改訂の「§6 撤回」を一部改める（`/contact` には出さない点は変えない）。
- プライバシーポリシー: B と A は今の Cloudia と同じ項目を新しい経路で集める。#382 の第10項と L8（同意の文言）に響く。ポリシーはこの ADR では直さない。
- 本番の Worker のデプロイと、Turnstile の秘密情報の設定は、代表が行う（手順は B を入れる PR に書く）。

## 決めてほしいこと（代表）

1. 推し案（B をいま足す、A は測ってから、F は弁護士の確認の後）でよいか。
2. B の伝言の入口を、Cloudia の最初の画面にも出すか、会話の途中と障害時のページだけにするか。
3. 本番のデータを読んでよいか。読むなら、どれか（調査の文書の 2 節: D1 の集計 2 本、Cloudflare Web Analytics、`cloudia@cor-jp.com` の受信箱の件数、2026-09-13 より前のフォームの受信の件数）。
4. cor-jp.com の Google Workspace のエディション（A の道具が決まる）。
