# ADR-0029 会社の現在の事実は、記録と照合して書く（最初の対象は ISMS）

## ステータス: Proposed (2026-11-12)（決定の日と中身は末尾の「根拠」。決定の根拠の記録は、この repo の外で管理する。ISMS の表現の項は ADR-0007・ADR-0022 を置き換える）

ADR-0022 の決定 3 は「登録が完了したら ADR を改訂して表現を更新する」としていた。この ADR がその改訂にあたる。文体のゲートが持つ「いまの事実」の判断を、固定の禁止語から、記録との照合に替える。

## 背景

- ISMS（ISO/IEC 27001:2022）は 2026-11-07 に登録された（登録証の確認は 2026-11-11）。ADR-0007 と ADR-0022 は、登録前の表現（第 2 段階審査を終え、登録を見込んでいる。「取得済み」と書かない）を決めていた。
- その決まりは `cor_voice_lint.py` の固定の規則（`isms_obtained`）になっていた。登録のあとは、正しい文を止め、古い文を通す。公開している業種ページ 5 本の本文は、すべて error になった（Issue #526）。
- 固定の禁止語を消すだけだと、記録の無い認証（P マーク、SOC 2 など）や、範囲を広げた表明まで通る。コーポレートサイトとして許せない。
- 同じ事実が、ADR、cor-voice の SKILL、ゲートの SKILL、`AGENTS.md`・`CLAUDE.md`、`scripts/blog-guardrails.mjs`、`docs/story-spine.md` に別々に書かれていて、直し漏れが起きる（corsweb2024#523）。

## 決定

1. 現在の事実の記録は `.claude/skills/cor-voice/references/facts.json` に置く。ISMS は `id: isms` の 1 件で、状態（`status`）、規格、登録番号、登録範囲、発行者、有効期間、有効の条件、確認した日、根拠の所在、許す表明、広げてはいけない先、再確認の条件、履歴を持つ。公開されている事実だけを置く。登録証の画像・所在地・審査報告の中身は置かない。
2. `cor_voice_lint.py` は固定の規則をやめ、記録と照合する。止める形は次の 8 つで、どれも error である。
   - `cert_unverified`: 記録に無い認証を取得済みと書いている
   - `isms_status_mismatch`: 取得を現在の事実として書いているのに、記録の状態が `registered` でない、または検査日が有効期間の外
   - `isms_scope_overreach`: ISMS の表明を、個別製品・AI の回答精度・医療機器・機能安全・全事業・漏えいゼロ・万全へ広げている
   - `isms_scope_missing`: 取得を書く文と同じ段落に、登録範囲が無い（直後の段落は数えない。例外は見出しだけの行で、決定 4 の 2 つ目）
   - `isms_number_mismatch` / `isms_date_mismatch`: 登録番号、取得・登録の日付が記録と違う（確認した日を取得日にしない。審査・確認などの語があり、取得の語が無い節の日付は、別の出来事の日付として数える。「登録を完了しました」は取得の表明として照合する）
   - `isms_stale_state`: 記録が `registered` なのに、登録前の状態（登録を見込んでいる、整備中など）を現在の説明として書いている。日付つきの過去の記録は `--archive` で許す
   - `isms_validity_condition_missing`: ISMS の語がある同じ段落（箇条書き・表・引用は 1 行）に、有効期間の日付を書く文があるのに、記録の `validity_condition`（「有効期間中の維持審査にて登録の継続が認められる限り有効」）の文が同じ段落に無い。期限まで無条件に有効とは書かない
3. 記録が読めない、壊れている、必須のキーが無いときは `fact_record_invalid` の error で止める。固定の旧規則へは戻らない。
4. ISMS の書き方（ADR-0007 の「整備中表現のみ」と ADR-0022 決定 3 を置き換える）:
   - 取得済みと書いてよい。同じ段落に、記録の登録範囲を書く。記事・note・SNS・メールのどの媒体でも同じにする（decision_records の isms-policy-2026-11-12）
   - 見出しだけの行（`#` で始まる見出し行、または `**…**` だけの 1 行）にある取得の表明は、空行を 1 つまで挟んだ直後の段落と 1 つに数える。範囲がその直後の段落にあれば通す。広げないもの: 見出しの 2 つ先の段落、通常の段落どうし、箇条書きの項目どうし、表のセルどうし、見出しの下に段落が無い形（次も見出し、見出しで終わる）。見出しを持たない文（SNS の投稿文など）は同じ段落だけ。決まりは decision_records の isms-heading-2026-11-12
   - 番号・日付・発行者は、記録にある値だけを書く。発行者名は記録の `issuer` と一致するときに書ける（「審査機関名を書かない」はこの範囲で置き換える）
   - 範囲を、個別製品・AI の回答精度・医療機器・機能安全・全事業・漏えいゼロへ広げない。「万全」「完全」は使わない
   - 認証マークと登録証の画像は SNS・署名・note に載せない。文章で取得を伝えることとは分ける。JSON-LD に `hasCredential` を使わない方針（ADR-0022）は維持する
   - 記録に無い認証（P マーク、SOC 2、SCS、ISO/IEC 42001、JIS Q 15001、TISAX、CSA STAR など）は、取得済みと書かない。名前は記録の `unrecorded_certifications` に足す（一覧の外の認証は止まらない。限界を見る）
5. 記録は、維持審査の結果・範囲変更・停止等が判明した時に更新する。証書の有効期限（2029-11-07）と「有効期間中の維持審査にて登録の継続が認められる限り有効」という条件の両方を記録に持ち、期限まで無条件に有効とは扱わない。新しい固定の再確認日・周期は置かない（decision_records の isms-policy-2026-11-12）。記録を変えるのは、一次資料を確認したあと、PR で行う。
6. 決定の記録（`decision_records`）は、決めた日と決まりの中身を持つ。欄は `id`・`decided_at`（日だけ）・`summary` の 3 つだけで、ほかの欄が 1 つでもあれば、3 つのどれかが無ければ、記録は使えない（`fact_record_invalid`。観測した欄の名前を文に出す）。決定の根拠の記録は、この repo の外で管理し、`id` で対応づける。AI の推奨や、第三者の言い換えを、根拠として置かない。
7. 同じ判断を持つ場所は、記録を指す。値を写す場所には、片方を変えると落ちる試験を置く（`test_cor_voice_facts.py`、`scripts/__tests__/blog-guardrails-facts.test.mjs`）。`scripts/blog-guardrails.mjs` は事実の判断を持たず、`cor_voice_lint.py check --only-facts` をそのまま呼ぶ（動詞・範囲・番号の写しを JS 側に持たない）。取得の表明の語彙・古い状態の語・範囲を広げる語・認証名は、すべて記録（`facts.json`）に置く。
8. `cor-voice/` は griftai の CI が corsweb と同一であることを検査する。corsweb でこの変更が develop に入る日に、griftai へ同じ内容を写す。

## 限界（lint は床で、意味の確かめは人が行う）

反例の検査（2026-11-12）と、その後のレビュー（2026-11-15）で、次は閉じていない。ここに書いたものは、通っても「事実と合っている」とは言えない。

- 日本語以外の本文（英・中・韓・西の取得表明）。lint は日本語の文体の検査で、他言語の本文には当てていない
- 見出しと、取得を述べる文が別の段落にある形（「## ISMS取得のお知らせ」＋次の段落）。取得の検出は 1 文の中で ISMS の語と動詞が近いときだけ
- 範囲を広げる文を、取得の文とは別の段落に書く形（「ISMS 認証を取得しました。」の次の段落に「だから当社の AI は誤回答しません。」）。拡大の検査は ISMS の語がある同じ段落の文まで見る（箇条書き・表・引用は 1 行ごとに別の単位）。別の段落までは見ない
- 語の一覧の外の言い方（「情報漏洩はゼロ」など）
- `--archive` は lint の引数で、`scripts/blog-guardrails.mjs`（`npm run blog:check`）には指定する手段が無い。日付つきの過去の記録は、lint に `--archive` を付けると、古い状態の説明（isms_stale_state）と登録前の予定日（isms_date_mismatch）の両方が通る。お知らせ `isms-stage2-audit.md` の旧い節の 3 件は、blog:check と content-advisory の知らせ（止めない）に出続ける
- 記録に無い認証は、名前の一覧（`unrecorded_certifications`）で止める。一覧に無い名前の認証と、名前と取得の動詞の間が 24 字を超える形（「プライバシーマークについては、…所定の手続きを経て取得しました」）は止まらない
- 範囲を限る語（「範囲外」「対象外」「含まれません」など）は、否定の述語として節の終わりにあるときだけ、拡大を打ち消す（「Grift は登録範囲外です」は通り、「登録範囲外の Grift にも適用されます」は止まる）。節の終わりに続けてよい語は、言い切り（です・ます）、となります・としています、節を切る語（であり・で・が）、理由（からである・ため・ので）に限る。語のあとに別の語が続く形（「含まれません（注）」など、括弧の中に長い注が入る形）は、打ち消されず止まる（安全側）
- 正しく範囲を限った文でも、限定句の語の一覧の外の言い方（「登録範囲には含まれていません」「…ものではなく、…」）と、限定句のあとの理由が因果の語（「範囲外のため、別に管理しています」の「のため」）の形は、止まる。書き直して通す
- 有効の条件の規則は、ISMS の語がある同じ段落に、有効期間の日付を書く文があるときだけ見る。ISMS の語が無い段落の有効期間、日付の無い「有効期間中」の文は見ない。条件は記録の `validity_condition` の文字列で照合し、言い換えた条件は通らない。別の段落に条件があっても通らない。箇条書き・表は 1 行を 1 つの単位に数えるので、条件は同じ行（括弧の中など）に書く。見出し（「## ISMS の有効期間」）と、その下の段落にある日付は、見出しだけの行を束ねる決め（isms-heading-2026-11-12）がこの規則には効かないので、ISMS の語も「有効期間」の語も無い段落の日付として、見ない
- 和暦・英語の日付、別形式の登録番号（日付は月日が一致するかを見る。年は西暦の年がある場合だけ）
- 維持審査の結果・範囲変更・停止等は、機械で知る手段が無い。lint は記録の `status` と有効期間に従うだけで、期限の内側を無条件に有効とは断定しない。判明したら人が記録を更新する（decision_records の isms-policy-2026-11-12）
- 記事のタイトルだけが SNS に出る場面では、範囲が並ばない（decision_records の isms-heading-2026-11-12 の決めに伴う制約）。見出しと直後の段落を束ねる規則は、見出しだけが単独で出る場面を守らない
- frontmatter の `title`・`description` と OG の文言は、lint が特別扱いしていない（frontmatter も普通の行として読み、続く YAML の行は 1 つの段落に数える。OG は blog の title・description から作る）。この回では扱いを変えていない
- 誤検知（安全側の誤り）: 他社の取得、一般論の「製品」「安全性」「全社員」、過去の否定、引用、範囲の表記ゆれ（「ソフトウェア」）でも止まる。止まったら記録を広げず、文を書き直す

## 理由

- 事実が変わるたびにゲートの規則を直す方式は、今回のように登録の日に壊れる。事実を記録に置き、規則は記録を読む形にすると、更新は記録 1 か所になる。
- 日付が過ぎたら自動で取得済みにする、資料が見られないから未取得とする、という推定はしない。状態は記録に明示する。
- 範囲を併記させるのは、ISMS の認証が組織のマネジメントシステムに対するもので、製品や AI の回答精度の保証ではないからである。

## 影響

- 古い「12 月ごろ登録見込み」の表現は error になる。公開している業種ページ 5 本の本文は、見出しだけの行「ISMS認証取得済み」と次の段落を 1 つに数えるので、本文を変えずに通る。
- `AGENTS.md`・`CLAUDE.md` の ISMS の行、`docs/story-spine.md`、`docs/blog-style-guide.md`、ゲートの SKILL は、記録を指す文に変わる。
- サイトの値（`src/i18n/locales/*.json`、ページ）と記録を結ぶ試験は、サイトを所有する PR（#523）が作る。
- この ADR は、意味候補の処理記録・結果の履歴・ブロック別の検査（ゲートの別の変更）を決めない。

## 代替案

- 固定の禁止語を消すだけ: 記録の無い認証や範囲の拡大まで通るので採らない。
- 日付で自動的に取得済みへ切り替える: 登録証を見ていない状態を事実として書くので採らない。
- 事実の記録を、サイトの設定（`src/config/organization.ts`）に置く: griftai の CI が比べるのは `cor-voice/` なので、ゲートの記録は `cor-voice/` に置くほうが同期の仕組みを増やさない。

## 根拠（決定の記録）

この ADR の決まりは、次の 2 つの決定に基づく。決定の根拠の記録は、この repo の外で管理する。この repo には、`facts.json` の `decision_records` に、`id`・`decided_at`（日だけ）・`summary` の 3 つだけを置く。

- `isms-policy-2026-11-12`（2026-11-12）: ISMS の認証取得を文章で述べるときは、SNS を含め同じ段落に登録範囲を併記する（isms_scope_missing）。記録は、維持審査の結果・範囲変更・停止等が判明した時に更新し、有効期限（2029-11-07）と有効の条件を保持して、期限まで無条件に有効とは扱わない（recheck、isms_status_mismatch）。決定の根拠の記録は、この repo の外で管理し、id で対応づける（decision_records の検査）
- `isms-heading-2026-11-12`（2026-11-12）: 見出しだけの行（# の見出し行か、太字だけの 1 行）にある取得の表明は、空行を 1 つまで挟んだ直後の段落と 1 つに数える。2 つ先の段落、通常の段落どうし、箇条書き・表のセル・引用、見出しの下に段落が無い形は広げない（isms_scope_missing）
