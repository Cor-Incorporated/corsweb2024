# ADR-0029 会社の現在の事実は、記録と照合して書く（最初の対象は ISMS）

## ステータス: Proposed (2026-11-12)（寺田さんの回答 2026-11-12 に基づく。ISMS の表現の項は ADR-0007・ADR-0022 を置き換える）

ADR-0022 の決定 3 は「登録が完了したら ADR を改訂して表現を更新する」としていた。この ADR がその改訂にあたる。文体のゲートが持つ「いまの事実」の判断を、固定の禁止語から、記録との照合に替える。

## 背景

- ISMS（ISO/IEC 27001:2022）は 2026-11-07 に登録された（登録証の確認は 2026-11-11）。ADR-0007 と ADR-0022 は、登録前の表現（第 2 段階審査を終え、登録を見込んでいる。「取得済み」と書かない）を決めていた。
- その決まりは `cor_voice_lint.py` の固定の規則（`isms_obtained`）になっていた。登録のあとは、正しい文を止め、古い文を通す。承認済みの業種ページ 5 本の本文は、すべて error になった（Issue #526）。
- 固定の禁止語を消すだけだと、記録の無い認証（P マーク、SOC 2 など）や、範囲を広げた表明まで通る。コーポレートサイトとして許せない。
- 同じ事実が、ADR、cor-voice の SKILL、ゲートの SKILL、`AGENTS.md`・`CLAUDE.md`、`scripts/blog-guardrails.mjs`、`docs/story-spine.md` に別々に書かれていて、直し漏れが起きる（corsweb2024#523）。

## 決定

1. 現在の事実の記録は `.claude/skills/cor-voice/references/facts.json` に置く。ISMS は `id: isms` の 1 件で、状態（`status`）、規格、登録番号、登録範囲、発行者、有効期間、有効の条件、確認した日、根拠の所在、許す表明、広げてはいけない先、再確認の条件、履歴を持つ。公開されている事実だけを置く。登録証の画像・所在地・審査報告の中身は置かない。
2. `cor_voice_lint.py` は固定の規則をやめ、記録と照合する。止める形は次の 7 つで、どれも error である。
   - `cert_unverified`: 記録に無い認証を取得済みと書いている
   - `isms_status_mismatch`: 取得を現在の事実として書いているのに、記録の状態が `registered` でない、または検査日が有効期間の外
   - `isms_scope_overreach`: ISMS の表明を、個別製品・AI の回答精度・医療機器・機能安全・全事業・漏えいゼロ・万全へ広げている
   - `isms_scope_missing`: 取得を書く文の同じ段落か直後の段落に、登録範囲が無い
   - `isms_number_mismatch` / `isms_date_mismatch`: 登録番号、取得・登録の日付が記録と違う（確認した日を取得日にしない）
   - `isms_stale_state`: 記録が `registered` なのに、登録前の状態（登録を見込んでいる、整備中など）を現在の説明として書いている。日付つきの過去の記録は `--archive` で許す
3. 記録が読めない、壊れている、必須のキーが無いときは `fact_record_invalid` の error で止める。固定の旧規則へは戻らない。
4. ISMS の書き方（ADR-0007 の「整備中表現のみ」と ADR-0022 決定 3 を置き換える）:
   - 取得済みと書いてよい。同じ段落か直後の段落に、記録の登録範囲を書く。記事・note・SNS・メールのどの媒体でも同じにする（2026-11-12 の寺田さんの回答）
   - 番号・日付・発行者は、記録にある値だけを書く。発行者名は記録の `issuer` と一致するときに書ける（「審査機関名を書かない」はこの範囲で置き換える）
   - 範囲を、個別製品・AI の回答精度・医療機器・機能安全・全事業・漏えいゼロへ広げない。「万全」「完全」は使わない
   - 認証マークと登録証の画像は SNS・署名・note に載せない。文章で取得を伝えることとは分ける。JSON-LD に `hasCredential` を使わない方針（ADR-0022）は維持する
   - 記録に無い認証（P マーク、SOC 2、SCS など）は、取得済みと書かない
5. 記録を変えるのは、一次資料を寺田さんが確認したあと、PR で行う。維持審査の結果が出たら、寺田さんが記録を更新する。それまでは有効期間の終わり（`valid_to`）まで有効として扱い、別の期限の日付は置かない。
6. 同じ判断を持つ場所は、記録を指す。値を写す場所には、片方を変えると落ちる試験を置く（`test_cor_voice_facts.py`、`scripts/__tests__/blog-guardrails-facts.test.mjs`）。`scripts/blog-guardrails.mjs` は状態と古い表現と記録に無い認証だけを見て、範囲・番号・日付は lint が見る。
7. `cor-voice/` は griftai の CI が corsweb と同一であることを検査する。corsweb でこの変更が develop に入る日に、griftai へ同じ内容を写す。

## 理由

- 事実が変わるたびにゲートの規則を直す方式は、今回のように登録の日に壊れる。事実を記録に置き、規則は記録を読む形にすると、更新は記録 1 か所になる。
- 日付が過ぎたら自動で取得済みにする、資料が見られないから未取得とする、という推定はしない。状態は記録に明示する。
- 範囲を併記させるのは、ISMS の認証が組織のマネジメントシステムに対するもので、製品や AI の回答精度の保証ではないからである。

## 影響

- 承認済みの業種ページ 5 本の ISMS の部分は、本文を変えずに通る。古い「12 月ごろ登録見込み」の表現は error になる。
- `AGENTS.md`・`CLAUDE.md` の ISMS の行、`docs/story-spine.md`、`docs/blog-style-guide.md`、ゲートの SKILL は、記録を指す文に変わる。
- サイトの値（`src/i18n/locales/*.json`、ページ）と記録を結ぶ試験は、サイトを所有する PR（#523）が作る。
- この ADR は、意味候補の処理記録・結果の履歴・ブロック別の検査（ゲートの別の変更）を決めない。

## 代替案

- 固定の禁止語を消すだけ: 記録の無い認証や範囲の拡大まで通るので採らない。
- 日付で自動的に取得済みへ切り替える: 登録証を見ていない状態を事実として書くので採らない。
- 事実の記録を、サイトの設定（`src/config/organization.ts`）に置く: griftai の CI が比べるのは `cor-voice/` なので、ゲートの記録は `cor-voice/` に置くほうが同期の仕組みを増やさない。
