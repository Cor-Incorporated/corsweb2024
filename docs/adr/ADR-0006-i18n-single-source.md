# ADR-0006 i18n source of truth を `src/utils/i18n.ts` に一本化（`*.json` 廃止）

## ステータス: Superseded (2026-09-27)

旧ステータス: Accepted (2026-06-13)。実装は逆方向に進んだ: 2026-07-06 のリファクタ（#209, 9d96cbc）で翻訳データは言語別 JSON `src/i18n/locales/{ja,en,zh,ko,es}.json` に外部化され、`src/utils/i18n.ts`（60 行）は型付きローダーになった。現在の正本は locales の JSON で、「単一の正本を持つ」という本 ADR の意図はこの形で満たされている。以下は当時の記録。

## 背景
- i18n の実体は `src/utils/i18n.ts`（2303行・全データ直書き・5言語 ja/en/zh/ko/es＝実査確認）。
- 一方 `src/i18n/*.json`（ja.json／en.json／*.d.ts のみ存在・zh/ko/es 無し）は**どこからも読まれない死蔵**で、編集しても反映されない罠になっている。
- `ja.json` に TapForge 等の旧事業文言が残存しており、誤参照・旧事業表現の潜在復活経路になるリスクがある（ADR-0007 ガードレール）。

## 決定
- i18n の source of truth を **`src/utils/i18n.ts` に一本化**する。
- **死蔵の `src/i18n/*.json`（および `*.json.d.ts`）を削除**する。参照0を grep 確認後に削除する。
- C案全コンポーネントの i18n キーは `src/utils/i18n.ts` に5言語同形で追加する（ja 確定→他言語後追い運用、AI/法務/ISMS 用語は人手確認）。

## 理由
- 二重定義（i18n.ts と *.json）は「編集無反映の罠」と「旧事業文言の潜在復活経路」を生む。正本を一本化することで運用事故と対外表現ガードレール違反のリスクを断つ。
- 実際にアプリが参照しているのは i18n.ts であり、これを正本とするのが実態整合。

## 影響
- `src/i18n/` 削除後に build・型チェックが通ることを確認する（参照0前提）。
- 旧事業文言（TapForge/BoltSite/IoTRealm 等）の潜在参照経路が消滅する。
- 削除実行は担当を一本化し重複・編集衝突を避ける。
- 中期課題: i18n.ts が規約「ファイル800行未満」を大幅超過（2303行）。将来は locale 別ファイル分割（`src/locales/{ja,en,zh,ko,es}.ts`）＋型共有、または StudioCMS 一部移行を検討（技術的負債として Issue 化）。Wave1 は一本化を優先する。
- ja meta が英語文言（旧事業：Python data analysis 等）のまま残っている箇所を新事業・日本語へ差し替える（全5言語 meta の旧事業色を除去）。

## 代替案
- ***.json を正本に統一（i18n.ts を捨てる）**: 現在アプリが参照しているのは i18n.ts であり、2303行のデータ移植コストとリグレッションリスクが大きいため却下。
- **二重定義を維持**: 編集無反映・旧事業文言復活のリスクが残り、運用事故源となるため却下。
- **即時に locale 別分割へ移行**: Wave1 のスコープを膨らませ移行リスクが増すため、一本化を優先し分割は中期 Issue 化。
