# ADR-0007 対外表現ガードレール（ISMS・旧事業・社名・証拠ルール）

## ステータス: Accepted (2026-06-13) / **改訂 2026-07-10**（実績・数値の証拠ルールを追加） / **一部置換 2026-10-20**（ISMS 表現と Grift の項を ADR-0022 で置き換え）

## 背景
- HP刷新にあたり、認証・セキュリティ・事業内容・社名の対外表現に法的・信頼性のリスクがある。
- 2026-07-10 監査で、Works の「準備中」事例と「AI駆動開発 4〜5倍（内部実測）」など **根拠ページのない数値** が慎重な企業顧客に弱いと指摘された。
- Grift 現行にあった「営業時間 80%」「提案 3日→1日」は検証データなしでは復活させない。

## 決定

### 従来ガードレール（維持）
- ~~**ISMS は「整備中」表現のみ**~~ → **ADR-0022 で置換**: 第2段階審査の終了（2026-10）と登録見込み（2026-12 ごろ）までは書いてよい。登録完了まで「取得済み／認証取得」は禁止。審査機関名の断定禁止は維持。
- **Pマーク / SCS は公開文面から除外**。
- **旧事業（TapForge / BoltSite / IoTRealm / IoT / IT戦略コンサル）を全撤去**。
- **社名は「Cor.株式会社」に統一**（ブランド表記 Cor.inc を使う場合も会社情報では正式名称を明示）。
- JSON-LD `Organization` に `hasCredential` を使わない。
- 絶対表現・架空 Testimonials・顧客名の無許諾掲載禁止。
- ~~Grift は「参考見積もり」とし「確定見積もりを出す」断定をしない。~~ → **ADR-0022 で置換**: Grift は見積支援ではなく「git履歴から確かめられる事実を取り出す自社プロダクト（CLI は OSS）」。点数・順位を出すとは書かない。

### 証拠・数値ルール（2026-07-10 追加）
1. **「準備中」の事例を公開実績一覧に出さない**。載せるなら「研究・検証テーマ」等に分類し、実績と混在させない。
2. **内部実測・倍率・削減率**（例: 「AI駆動開発 4〜5倍」）は、対象タスク・比較条件・期間・測定方法を示すページへリンクできる場合のみ掲載。説明できない場合は **削除**。
3. 匿名事例でも最低限 **期間 / 対象業務 / 実装範囲 / 結果 / 顧客側の運用** を揃える。
4. Grift の **「営業時間 80%」「提案 3日→1日」** は検証データが整うまで掲載禁止（復活禁止リスト）。
5. 「30秒で試す」等の時間約束は、その場で完了する機能がある場合のみ。未実装なら文言を真実に合わせる（ADR-0010）。

## 理由
- 未取得認証・誇大表現は法的・信頼性リスク。
- 根拠のない数値は士業・建設・製造の購入判断者の信頼を下げ、有料入口（診断 10〜30万等）と矛盾する。

## 影響
- 公開対象に対し禁止語 grep に加え、実績「準備中」・未根拠倍率のチェックを公開前ゲートに含める。
- Works / Home の数値バッジ / Grift コピーを Issue で是正する。

## 代替案
- **内部実測を注記なしで残す**: 監査で不合格のため却下。
- **準備中カードを「Coming soon」として残す**: 実績一覧では不可。別セクションなら可。
