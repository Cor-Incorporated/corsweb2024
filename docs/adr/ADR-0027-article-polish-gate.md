# ADR-0027 記事とニュースの推敲を、ツールに依存しないゲートにする

## ステータス: Proposed (2026-10-28)

ADR-0026 の「規則の本文は 1 か所、入口は参照だけ」を、ブログとニュースの原稿に対する実行手順へ落とす。CMS の作成・更新・削除はこの ADR では変えない。

## 背景

- 日本語の推敲は yomiyasu、場面と表現ルールは cor-voice が持つ。どちらも `.claude/skills/` にあり、本文をツールごとに写すと古くなる（ADR-0026）。
- CMS（Sveltia、ADR-0018）は、ブログの ja を PR として作成・更新できる。削除はできず、news はまだ対象外である。原稿が CMS から来ても、エージェントの PR から来ても、推敲の入口は別々だった。
- 場面（会社として書く、代表の名前で書く、技術の記事）は、カテゴリだけで決まらない記事がある。engineering の多くは会社の解説で、検証記事だけが技術の記事である。エージェントが原稿を読んだ印象で場面を変えると、一人称や文の長さが入れ替わる。
- 採用した記事を次の推敲の見本にする仕組みが無い。会話のメモリに残すと、レビューできず、ツールを変えると消える。

## 決定

1. 推敲の入口は `npm run polish`（`scripts/polish/cli.mjs`）の 1 つにする。Cursor、Codex、Claude Code、Pi、dsh、OpenCode、Grok は、このコマンドを実行する。手順を置くファイルは `skills/article-polish/SKILL.md` で、ツールごとのファイルはそこへの参照だけにする。Cursor で対象ファイルを開いたときは `.cursor/rules/japanese-copy.mdc` が同じコマンドを指す。
2. 対象は `src/content/blog/ja/` と `src/content/news/ja/`。翻訳ファイルは対象外。cases は対象外のままにする。
3. 場面の既定は blog の ai と engineering を会社、founder を代表、lab を技術、news を会社とする。別の場面にするのは、人間の指示文に明示の印があるときだけとする。印が無い指示は言い回しの指定として `docs/polish/instructions/` に残り、場面は既定のままとする。印が複数あるときはコマンドを止める。
4. `prepare` は、同じ場面の公開済み ja 記事から抜粋を最大 3 件選ぶ。下書きと、対象のファイル自身は除く。見本の事実と数値は、新しい記事に写さない。
5. 採用した記事は ja としてマージされた時点で次の見本になる。人間が残したい書き方は `npm run polish -- learn --approved` で `docs/polish/learned/` に抜粋とメモを残す。全文と、モデルの内部状態は保存しない。cor-voice の本文はこのコマンドでは変えない（変更は ADR-0026 の、人が承認する PR）。
6. `check --file <原文> --final <最終稿>` が終了コード 0 かつ `complete: true` のときだけ、推敲の完了とする。ガードレール、場面の一人称、感嘆符、「試行」、社名、原文に無かった断定、yomiyasu の `run` と `verify` を含む。`--no-yomiyasu` は完了にしない。
7. 管理画面には推敲のボタンを足さない。ADR-0018 の第 1 段階どおり、CMS の画面に AI は入れない。

## 理由

- コマンドが 1 つなら、ツールが増えても呼び出し方を増やさない。規則の本文を写さないので、ADR-0026 の決定 1 を崩さない。
- 場面の切り替えを、レビューできるファイルの明示の印に限ると、エージェントの判断で一人称が入れ替わらない。
- 見本を公開原稿と、短い抜粋ファイルに限ると、何を学習したかを PR の差分で読める。埋め込みや非公開のメモリは、後から確かめられない。

## 影響

- 記事やニュースをエージェントが書くときは、PR の前に `npm run polish` を実行する。CI はこの ADR では検査を必須にしない（ADR-0026 の検査は別の作業）。
- `docs/polish/learned/` と `docs/polish/instructions/` はサイトには出さない。Content Collection の外に置く。
- 採用のたびに learned のファイルが増える。1 記事 1 ファイルで、全文は入らない。

## 代替案

- 場面をエージェントに選ばせると、engineering の解説と検証が入れ替わる。採らない。
- 見本をベクトルデータベースに置くと、差分でレビューできない。採らない。
- learn が cor-voice を直接書き換えると、人が承認する前に規則が変わる。ADR-0026 に反するので採らない。
- CMS の画面に推敲ボタンを足すのは、ADR-0018 の第 2 段階の話なので、この ADR の範囲外にする。
