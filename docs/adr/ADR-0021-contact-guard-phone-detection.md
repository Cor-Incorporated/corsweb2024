# ADR-0021 /contact 回帰ガードの電話検出（判定の対象・電話番号・句）

## ステータス: Accepted (2026-09-28) / **改訂 2026-09-28**（再レビュー: スクリプトが表示する文言・桁数で落ちた候補の探し直し・不可視の文字・否定の絞り込み・入力欄の値・JSON-LD の電話）

## 背景

- Issue #323 の回帰ガード（`src/config/contact-guards.ts`）で、電話の検出を 3 回続けて個別に直した（PR #331: L6 で番号を追加 → 再レビュー LOW-1 / LOW-2 → 最終レビュー MEDIUM-1）。
- 3 回目は、前回の修正（f8ffa5c）が検出範囲を狭めた退行だった。英字のラベルに直結した番号（`TEL092-000-0000`・`Tel092-…`・`FAX/TEL092-…`・`℡092-…`）を、6fb4722 では検出していたのに 8845499 では見逃した。`TEL` は電話を指す語のパターンに無いため、日本語サイトで多い表記が /contact に戻っても verify は緑のまま通る。
- 原因は 3 つ。
  1. HTML の outerHTML を照合していた（タグで分断された句を拾えない。`&nbsp;` のような文字参照が文字列のまま残り、NFKC 正規化が効かない）。
  2. 区切り文字を列挙していた（U+2212・U+30FC・U+2015 のような表記揺れが出るたびに追記が要る）。
  3. 番号の直前の文字を一律に制限していた（英数字の ID の途中を避けるための制限が、ラベル直結の番号まで落とした）。
- 同型の修正が 3 回目になったため、個別の修正をやめて判定の設計を決める（開発ルール「同型 fix 3 回目は ADR 化」）。

## 決定

### 1. 判定の対象は「読み手に届く文字列」

- 照合するのは HTML の outerHTML ではなく、次をつないだ文字列（`readableTextOf`）。
  - 本文の textContent。タグは除き、文字参照は解決済みの文字として扱う。行内要素（`strong`・`span`・`a` など）は区切らずにつなぎ、ブロック要素（`p`・`div`・`li`・`td` など）の境界には改行を入れる。
  - 人が読む属性: `alt`・`title`・`aria-label`・`placeholder`、入力欄の `value`（`type` が `hidden`・`password` のものを除く）、`option` / `optgroup` の `label`。
  - 検索結果や SNS のカードに出る meta の `content`: `description`・`og:title`・`og:description`・`twitter:title`・`twitter:description`。
  - JSON-LD（検索結果に表示されうる構造化データ）。
- 含めないもの: 実行用の `script`、`style`、`template`、上記以外の属性（`class`・`id`・`data-*`・`href`・`src`・SVG の `d` など）。
- **スクリプトが表示する文言は、実行後の DOM で見る。** 静的な HTML では `data-*` などの属性に入っていて、スクリプトが実行時に本文へ差し込む文言がある（例: CloudiaLauncher の `data-fallback-same-page` は、/contact 上でチャットを開けないときに表示される）。これは静的な照合では対象外になるので、dist 検査でそのスクリプトを実行した後の DOM に同じ判定を当てる。「チャットが落ちたら電話を案内する」は #323 の回帰として最も起きやすい形なので、ここを抜けにしない。
- 照合の前に NFKC で正規化する（全角→半角、`℡`→`TEL`、NBSP→空白）。続けて不可視の書式文字（`\p{Cf}`: U+200B ゼロ幅スペース・U+00AD ソフトハイフン・U+2060 ワードジョイナーなど）を取り除く。空白の連続は 1 つの空白にまとめる。ブロック境界の改行は残す。
- `tel:` リンクは文字列ではなく、属性（`a` / `area` の `href`）で別に見る。
- JSON-LD の `telephone` / `faxNumber` は電話導線として検出する（語と番号の両方が当たる）。入れるなら特商法ページ固有の JSON-LD に限り、全ページ共通の Organization には入れない。変えるときは本 ADR を改訂する。

### 2. 電話番号

- 区切り文字は列挙せず、文字クラスで扱う。
  - 空白（NBSP を含む。ブロック境界の改行は含めない）
  - `\p{Pd}`（Unicode のダッシュ類。`-`・`‐`・`–`・`—`・`―` などを含む）
  - `.`・`−`（U+2212）・`ー`（U+30FC）
  - 括弧（市外局番と中間の群を囲む `(092)`・`(1234)`）
  - 1 か所の区切りは 3 文字まで（`092 - 000 - 0000`）。
- 形: 国内は `0` で始まる 3 群。国際は `+81` の後に（`(0)` を挟んでもよい）3 群。
- 桁数で絞る: 区切りを除いた桁数が、国内は 10〜11 桁、`+81` は国番号を除いて 9〜10 桁のものだけを番号とする。日付（`09-27-2026` は 8 桁）はここで落ちる。
- 桁数で落ちた候補は、その候補の先頭の次の位置から探し直す。候補の終わりから続けると、落ちた候補が直後の本物の番号の先頭を飲み込み、その番号が二度と試されない（`受付時間 9:00〜18:00 092-000-0000` では候補 `00 092-000` が落ち、続く番号を見逃していた）。
- 番号の直前:
  - 行頭、または英数字・`+`・`/`・`.`・`-` 以外の文字の後なら検出する（「電話092-…」「：」の後なども含む）。
  - 英数字の直後は、それが単独のラベルのときだけ検出する: `TEL`・`Tel`・`tel`・`TEL.`・`FAX/TEL`・`Phone`・`FAX`（`℡` は NFKC で `TEL` になる）。ラベルの前が英字なら単独とみなさない。
  - 英数字の ID の途中（`A012-34-5678`・`hotel0120…`・`Intel090…`）は検出しない。

### 3. /privacy の句

- 1 と同じ文字列に対して判定する。タグで分断された句（`お<strong>電話</strong>でのお問い合わせ`）も 1 つにつながる。
- 否定の除外は ja だけで、同じ句の直後（助詞「は・も・では・を・に」と読点を挟んでもよい）に否定が続く場合に限る。文の離れた位置の否定（「営業時間外は受け付けておりません」「メールでの予約変更はできません」）では除外しない。
- 否定とみなす語は「受け付けておりません」「できません」「ご遠慮ください」のように、それだけで否定になる形に限る。「ご遠慮なく」のような肯定の言い回しを否定と取り違えない。

### 4. 誤りの向き

- 見逃しより誤検知を許容する。誤検知はテストが落ちて人が見る（fixture に 1 行足して判定を直すか、その表現を避ける）。見逃しは誰も気づけない。

### 5. 見逃し・誤検知の追加手順

- 実例は `tests/fixtures/phone-detection-cases.ts` に 1 行足すだけでよい。ユニットテストがその行を検出する／しないを検査する。
- 判定を変えるときは、この fixture が全件通ることを条件にする。

## 理由

- outerHTML を照合すると、読み手に届かない文字列（`class`・`data-*`・SVG のパスデータ・base64）で誤検知し、読み手に届く表記（タグで分断された句・NBSP）を見逃す。照合の対象を「読み手に届く文字列」に揃えると、両方が同時に減る。
- `\p{Pd}` は Unicode のダッシュ類をまとめて含むので、表記揺れのたびに区切り文字を足さなくてよい（Pd に入らない `−`・`ー` だけを明示する）。
- 番号の直前の制限は「英数字の ID の途中を避ける」ためのもの。ラベルを明示して例外にすれば、ラベル直結の番号と両立する。

## 影響

- `contact-guards.ts` の判定の中身が変わる。公開している関数（`findPhoneLeads`・`findPhoneInquiryPhrases`・`findPhoneInquiryLeads`）の入出力は変えない。
- `format-detection` の meta（`content="telephone=no"`）は属性なので自然に対象外になり、除外リストは要らなくなる。
- 実 dist（481 ページ、カレンダーあり・なしの 2 回のビルド）で、番号を検出するのは特商法ページの 5 言語だけ。/contact と /privacy は 0 件（2026-09-28 実測）。

## 代替案

- outerHTML のまま前後の制限を調整する（前回までの方式）: 退行を繰り返したので採らない。
- 電話番号ライブラリ（libphonenumber など）: 新規依存を足さない方針（#323）であり、目的は日本語の地の文に埋まった番号の抽出なので採らない。
- 否定を全言語で扱う: 誤った除外で見逃すほうが害が大きく、ja 以外の実例が無いので見送る。

## 既知の限界

- ja 以外の否定文（"We do not accept phone inquiries" など）も検出する（誤検知の側）。
- 番号の直後に英字が続く表記（`092-000-0000FAX`）も検出する（誤検知の側）。
- 0 始まりで 10〜11 桁の数字（JSON-LD の ID など）は番号として検出しうる（誤検知の側。現行の dist では 0 件）。
- ブロック境界をまたぐ番号（表の別々のセルに分かれた市外局番と番号）は検出しない。
- 画像の中の文字と、CSS の `content` で出す文字は対象外。
- `iframe` の `srcdoc` は対象外（中身は別の文書で、サイトでは使っていない。使うときは本 ADR を改訂する）。
- 実行後の DOM で見ているのは dist 検査で実行するスクリプト（CloudiaLauncher）の文言だけ。ほかのスクリプトが実行時に差し込む文言は検査していない。
