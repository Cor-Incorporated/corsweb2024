# Cor. ブログ文体ガイド（社長の書き方メモリ）

このファイルは、会社の名前で書くブログ記事（ai・engineering カテゴリの解説記事）の書き方です。
代表・寺田康佑の書き方の特徴と、場面ごとの文体（代表の名前で書く記事、技術の記事を含む）は cor-voice スキル（`.claude/skills/cor-voice/SKILL.md`）にまとめています。
書いたあとは yomiyasu スキル（`.claude/skills/yomiyasu/`）で推敲します。

## 読者
日本の中小企業の経営者・管理部門・現場リーダー。ITやAIの専門家ではないが、現場の課題感は強い人。

## トーン（最重要）
- **「お手伝い目線」**。「Cor.は〇〇できます／実現します」と自社の能力を断定・誇示しない。
  - ❌「AIで業務を50%削減できます」「弊社が貴社のDXを実現します」
  - ✅「〇〇を一緒に整理するお手伝いができます」「〇〇に向けて伴走します」「〜を目指せます」
- 専門用語は最小限。使うときは1行で噛み砕く（例:「RAG（社内文書をAIに参照させる仕組み）」）。
- 上から目線・煽り・不安商法はしない。読者を「素人」「初心者」と見下す表現は禁止。
- 落ち着いた、誠実で、現場に寄り添う語り口。一人称は基本「Cor.」。

## 構成（標準テンプレート）
1. **問いかけ/共感の導入**（2〜3文）— 読者の「あるある」な困りごとから入る。
2. **## 何が起きているのか**（背景・なぜ難しいか。一般論＋必要なら最新動向）
3. **## よくあるつまずき**（2〜4個、現場の言葉で）
4. **## どう進めるか**（手順や考え方。Cor.の実サービス＝AI受託開発／AI顧問・研修／ローカルLLM・セキュアAI／Grift に自然に接続）
5. **## まとめ**（短く）
6. **## よくある質問**（任意）
7. **## 参考資料**（出典のリンクの箇条書き。最後の h2 にする）

本文に相談の見出しやリンクは書かない。記事の下に CTA ボックスが 1 つ出る（ADR-0020）。案内する相談はカテゴリの既定値で、変えるときは frontmatter の `ctaIntent` を使う。
frontmatter の `summary` に、記事の結論を 2〜3 文で書く（本文の前の「この記事の要点」に出る）。

## 事実・出典のルール（厳守）
- 数値・統計・調査結果を書くなら、一次情報の出典を必ず併記する（記事末尾の「## 参考資料」に実在するURLで。この節のリンクは構造化データの出典にもなる）。
- **存在しないデータ・事例・顧客名・実績・数値を絶対に作らない（捏造禁止）**。確証がなければ書かない。
- 出典URLは実在するものだけ。`cor-jp.com` 以外の自社プレビューURL（`*.web.app`）や下書きキー付きURLは載せない。

## ガードレール（公開前必須・違反は不可）
- 公開禁止の旧事業名は使わない: TapForge / BoltSite / IoTRealm / IoT戦略 / IT戦略コンサル。
- 未取得の認証を「取得済み」と書かない。ISMS は「2026年10月に ISO/IEC 27001 の第2段階審査を終え、2026年12月ごろの認証登録を見込んでいる」まで（ADR-0022）。Pマーク/SOC2 等の取得主張は禁止。
- Grift は見積もりのツールではない（ADR-0022）。git 履歴から確かめられる事実を取り出す自社プロダクト（OSS の CLI）と、紹介会社さま向けのテスト導入（PoC）として書く。
- 「確実に」「絶対に」「必ず儲かる」等の断定・効果保証はしない。

## 体裁
- 見出しは `##` / `###`（記事タイトルは frontmatter 側で表示するので、本文先頭に h1 を重複させない）。
- 本文は日本語。1記事あたり本文 1,500〜2,800字程度。
- 箇条書き・短い段落で読みやすく。コードや手順は必要なときだけ。
- Grift へのリンクは `https://griftai.org`（ページやコンポーネントでは `PUBLIC_GRIFT_BASE_URL` 経由。ADR-0010）。

## 扱うテーマの範囲
AI導入 / DX / 生成AIの社内活用 / ローカルLLM・セキュアAI / RAG・社内ナレッジ / PoC・KPI / AI駆動開発 / 業務自動化 など、中小企業の実務に効くもの。流行語の解説で終わらせず「現場でどう使うか」に着地させる。
