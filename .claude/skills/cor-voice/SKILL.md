# cor-voice

Cor.株式会社と Grift の公開文を、代表・寺田康佑（terisuke）の書き方に寄せるための調整です。
推敲の規則そのものは yomiyasu スキル（`.claude/skills/yomiyasu/`）に従います。このスキルはその上に「どの場面でどの文体にするか」「本人の書き方の何を残し、何を持ち込まないか」「サイトで書いてはいけないこと」を足します。

食い違ったときは、次の順で優先します。

1. ADR の表現ルール（cor-jp.com は `docs/adr/`、griftai.org は `planning/` と CLAUDE.md が指す ADR）
2. yomiyasu の「意味の保持」と「情報の不増補」（主張、比重、言い切りの強さ、文の働き、数値、固有名詞を変えない。根拠のない事実を足さない）
3. このスキルの文体の指定

書き方の根拠は本人の公開記事 26 本（note 22 本、Qiita 4 本）と、Claude との会話での本人の発言です。調べた範囲と、AI の下書きらしい記事を手本から外した理由は `references/evidence.md` にあります。

## 1. 進め方

1. 文章の場面を下の「2. 場面ごとの文体」から 1 つ選ぶ。選べないときは、ページの持ち主（会社か、代表個人か）と読み手で決める。
2. yomiyasu の文書の種類を決める。LP やサービスの紹介文は promo、コラムと解説記事は article、操作の説明は manual、規約やポリシーは formal、架空の物語は essay。読者は経営者・営業・採用担当向けなら informed、エンジニア向けの技術記事なら expert にする。
3. yomiyasu の Step 1〜5 で推敲する。検査（`yomiyasu_check.py run` と `verify`）は省かない。
4. 3 の結果に、このスキルの「3. 本人の書き方で残すもの」「4. 持ち込まないもの」を当てる。ここでも意味と数値は変えない。
5. 「5. サイトの表現ルール」と、リポジトリの検査（下の「6. 検査」）を通す。

既存の文章を直すときは、文体を寄せるために事実や主張を足さない。本人らしい問いかけや結びを足したくなっても、原文と資料にない中身は書かない。新しく書くときも、数値、実績、社名、人の発言は資料にあるものだけを使う。

## 2. 場面ごとの文体

### 会社として書く文章

cor-jp.com のページ、サービス紹介、会社概要、FAQ、ブログの解説記事（ai・engineering カテゴリの多く）、griftai.org の LP・料金・FAQ・コラムが当たる。

- です・ます調。主語は「Cor.株式会社では」「Cor.」「Grift は」。会社の文章で「僕」「私」は使わない。
- 1 文は短め（平均 30 字前後）。1 段落は 1〜3 文。
- 読み手が次に何をすればよいかを、最後に 1 か所だけ書く。

### 代表の名前で書く文章

founder カテゴリの記事、note や Qiita からの転載、代表のあいさつが当たる。

- 自称は「僕」。2026 年の記事と同じく、です・ます調を基本に、短い言い切りを挟んでよい（「7倍になった。」「それは、おかしい。」）。
- 1 文 1 段落の短い区切りを使ってよい。
- 経歴は細部で語るか、1 行で済ませる（「僕は、もともとプログラマーじゃない。音楽をやっていた。営業もやった。」）。

### 技術の記事

lab・engineering カテゴリの検証記事、Grift CLI の使い方、Qiita 型の記事が当たる。

- です・ます調。手順、表、箇条書きを使ってよい（yomiyasu の manual と article の規則どおり）。
- 数字には定義、版、期間、分子と分母を付ける（「`0.2664` ではなく、`73 / 274` と読む」）。
- 何が言えて、何が言えないかを分けて書く。

### Grift のストーリー（架空の物語）

griftai.org の `/column/story-*` が当たる。

- 原文の文体（語りの常体・敬体）を保つ。架空の物語であることの表示は消さない。
- 登場人物の気持ちや比喩は yomiyasu の essay の規則どおり書き手の表現として残す。

## 3. 本人の書き方で残すもの

原文にこれらがあれば残し、言い換えで消さない。新しく書くときは、資料の範囲で使ってよい。

- 問いを重ねて、分からないことを具体にする。「でも、何を作ったのか。」「一人で作ったのか。チームで触ったのか。」
- 出さないもの、言えないことを先に書く。「Grift CLIは、技量の総合点を出しません。」
- 否定してから言い直す。「期間は必要です。ただ、期間をそのまま技量へ読み替えるのは違う。」
- 数字は出典、期間、定義と一緒に書く。「8月1日から23日までで2,907件。」「特に指定がなければ1人月を160人時…として扱っています。」
- たとえは 1 つだけ、理由と一緒に使う（健康診断の血圧のたとえ）。
- 結びは控えめにし、判断を読み手に返す。「判断するのは人間です。」
- うまくいかなかったことも書く。「効かなかった結果も、基準を下げずに公開する。」
- よく使う語は「確かめる」「検算」「事実」「違和感」「実測」。硬い言い方より、ふだんの言い方を選ぶ（代表の指摘で「試行」を「テストしてみる」に改めた）。

## 4. 持ち込まないもの

本人の公開記事にない、または AI の下書きで増えた型です。原文にあれば、yomiyasu の規則で直す。

- 大げさな決まり文句（「天元突破」「断言しよう」「未来を変える力」「〜と言っても過言ではない」）。
- 「〜とは何者か？」「〜とは？」の見出し、太字のラベルとコロンで始める箇条書き、ダッシュ（——、――）、「…」の多用。
- 感嘆符。2026 年の記事には 1 つもない。会社の文章でも使わない（引用と製品名は除く）。
- 方言の語尾（「〜んよね」「〜やん」）と「（笑）」。公開記事にはほぼなく、下書きでだけ増えていた。代表の名前で書く文章でも新しく足さない。
- 会社の文章での「。。。」「笑」などのくだけた記号。代表の名前で書く文章で原文にあれば残す。
- 一つの文章の中で「僕」と「私」を混ぜること。

## 5. サイトの表現ルール

詳しい決まりは各リポジトリの ADR と CLAUDE.md にあります。推敲で取り違えやすいものだけを挙げます。

- 社名は「Cor.株式会社」。ほかの表記（Cor.inc、Cor株式会社、読みがな付き）を新しく書かない。
- Grift はエンジニアの git 履歴から確かめられる事実を取り出す自社プロダクト（OSS の Grift CLI、MIT ライセンス）と、紹介会社・SES 企業・自社開発企業の採用担当向けのテスト導入（PoC）。見積もりのツールとは書かない。点数、順位、合否は出さない。採用担当向けの文でも、選考の合否や候補者の順位に使うとは書かない（Grift の利用規範）。2026 年 8 月の記事は Grift を「参考見積もり」の文脈で説明しているので、説明は写さない。
- 紹介会社向けの取り組みは「テスト導入（PoC）」、CTA は「自社でテストしてみる」。「試行」は使わない。
- 事業の柱は 5 本（Grift、ローカル LLM・セキュア AI、ハードウェア AI、AI 受託開発・導入支援、教育・コミュニティ）。順番と呼び方は ADR-0022 のとおり。
- ISMS は「2026年10月に ISO/IEC 27001 の第2段階審査を終え、2026年12月ごろの認証登録を見込んでいる」まで。「取得済み」「認証取得」と書かない。審査機関の名前を書かない。
- 名前を出してよい連携先はエンジニアカフェ（Engineer Cafe）だけ。「福岡を代表する企業100選」は書いてよい。
- 言い切りの保証（「確実に」「必ず」「絶対」）、根拠のない最上級、作った顧客名や声は書かない。社内の計測値や倍率は、条件を説明したページへのリンクがあるときだけ。
- CTA で「無料」を主な誘い文句にしない。価格を書かない（Grift の料金は個別案内）。
- 公表の確認が取れていない予定（大会への登壇、契約の内容など）は書かない。
- griftai.org の URL を cor-jp.com のコードに直接書かない（`PUBLIC_GRIFT_BASE_URL`）。

## 6. 検査

- yomiyasu: `python3 .claude/skills/yomiyasu/scripts/yomiyasu_check.py run --source 原文 --final 最終稿 --doc-type 種類 --fact-gaps`、提出の前に `verify --final 最終稿`。
- cor-jp.com: 記事は `npm run blog:check -- <ファイル>`、文言を変えたら `npm run check:links`、最後に `npm run build` と `npm run test:run`。
- griftai.org: `npm run check`（lint、書式、型、CTA、指標の検査）と `npm run build`。

## 7. このスキルの更新

本人の新しい記事が出たら、`references/evidence.md` の一覧に足し、特徴が変わっていれば 3 と 4 を直す。cor-jp.com と griftai.org の 2 つのリポジトリに同じ内容を置いているので、両方を同じに保つ。
