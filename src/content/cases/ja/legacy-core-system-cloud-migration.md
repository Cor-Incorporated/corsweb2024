## 課題

ある教育機関では、約25年分・225テーブル・約450万行・約11,000名分のデータが、長年運用されてきたSQL Serverの複数データベースとFileMakerに分かれて蓄積されていました。外部キー制約が定義されておらず、データ同士の整合性はアプリケーション側の運用で保たれている状態です。こうした「レガシーあるある」を抱えたデータを単純に移し替えるだけでは、25年分の暗黙知が引き継がれず、現場が混乱するリスクがあるとCor.は考えました。

## アプローチ

いきなりデータを移すのではなく、まず既存データベースを調査するところから始めました。調査では「確定した事実」と「確認が必要な仮説」を分けて整理することを大切にしました。テーブルの関係やデータの意味を、資料だけでなく現場の業務にも照らし合わせながら言語化し、仮説のまま設計に持ち込まないようにしました。移行先はGoogle Cloud(Cloud SQL / PostgreSQL + Cloud Run)とし、単純な複製ではなく今の業務に合わせた再設計を選んでいます。

## 実装

調査で明らかになった構造をもとに、多国籍の氏名を扱えるスキーマへ再設計しました。移行は一度に行わず段階を踏んで進め、各段階で第三者によるダブルチェックの体制を設けています。外部キー制約がなかった部分についても、データの関係性を洗い出し、整合性を見える形にしてから移行作業に反映しました。

- 移行元: SQL Serverの複数データベース + FileMaker(約25年分・225テーブル・約450万行・約11,000名分)
- 移行先: Google Cloud(Cloud SQL / PostgreSQL + Cloud Run)
- 工夫: 事実と仮説の仕分け、多国籍氏名対応のスキーマ再設計、第三者ダブルチェック

## 成果

段階移行は第2フェーズ(本番データベース移行)まで完了しています。事実と仮説を仕分けてから設計に入ったことで、これまで暗黙知に頼っていた整合性が見える形になり、運用担当者が抱えていた「このデータは本当に正しいのか」という不安を減らすことができました。25年分の積み重ねを尊重しながら、次の25年も安心して使える基盤へと引き継いでいく取り組みは、現在も続いています。
