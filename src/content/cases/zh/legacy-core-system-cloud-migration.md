## 课题

在某教育机构中，约25年、225张数据表、约450万行、约11,000人的数据，分散积累在长期运行的SQL Server多个数据库和FileMaker中。由于未定义外键约束，数据之间的一致性一直依靠应用程序端的运维来维持。Cor.认为，如果只是单纯迁移这些带有典型“遗留系统通病”的数据，25年来积累的隐性知识将无法传承，存在导致业务现场陷入混乱的风险。

## 方法

我们没有直接盲目迁移数据，而是首先从调研现有数据库入手。在调研中，我们非常注重将“已确定的事实”与“需确认的假设”区分整理。我们不仅参考资料，还对照业务一线的实际运作，将表之间的关系以及数据的含义转化为明确的语言描述，避免直接带着未经证实的假设进入设计阶段。迁移目标选定为Google Cloud（Cloud SQL / PostgreSQL + Cloud Run），且并非简单地复制，而是选择了契合当前业务的重新设计方案。

## 实施

基于调研中厘清的结构，我们重新设计了能够支持多国籍姓名的模式（Schema）。迁移并未一蹴而就，而是分阶段推进，并在各个阶段均设立了由第三方进行双重检查的机制。针对原本缺少外键约束的部分，我们也梳理出了数据之间的关联性，使数据一致性变得清晰可见后再落实到迁移工作中。

- 迁移源：SQL Server的多个数据库 + FileMaker（约25年、225张数据表、约450万行、约11,000人）
- 迁移目标：Google Cloud（Cloud SQL / PostgreSQL + Cloud Run）
- 巧思举措：区分事实与假设、支持多国籍姓名的模式重新设计、第三方双重检查

## 成果

分阶段迁移目前已完成至第2阶段（生产数据库迁移）。通过先区分事实与假设再进行设计，以往依赖隐性知识的一致性得以清晰呈现，减轻了运维人员此前一直抱有的“这些数据到底是否准确”的顾虑。在尊重25年沉淀的同时，将其交接转化为未来25年亦可安心使用的数据基石，这一工作目前仍在持续推进中。
